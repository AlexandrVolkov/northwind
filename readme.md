# Орда: Северный ветер — прототип на Godot

Ранняя версия на **Godot 4.7.2 .NET + C#**. По умолчанию запускается короткая **схватка в реальном времени** на первой карте: пять исходных отрядов Олега против замка и трёх защитников поселения Ильи. Выделяйте войско рамкой, отдавайте приказы движения/атаки и берегите предводителя.

**Цель:** разрушить красный замок и уничтожить его защитников. Гибель предводителя означает поражение. Кнопка **«Цель» / T** переводит камеру к замку, а после его разрушения — к оставшимся защитникам. Схватку можно начать заново клавишей **R**.

Это экспериментальная миссия, **не оригинальная кампания**. Начальная расстановка и кадры взяты из ресурсов игры; поворот, подготовка движения и перенос занятости используют проверенные по x86 операции. [Проходимость](docs/movement-admission.md) использует исходную проверку всей области SEG/DAT, включая наземные опоры; групповые цели и резервы учитывают размеры юнита. Локальный поиск маршрута уже перенесён из оригинала; для дальних тупиков остаются временные промежуточные цели AStar. Отношения двух поселений, боевой баланс, поведение защитников, частота тактов и визуальная анимация пока временные. Доступны [фермы, прирост свободных людей и наём ополченцев](docs/population-farms.md). Также доступен первый хозяйственный цикл: рабочие, рубка и доставка древесины, строительство лесопилки. Критерий леса, счётчики рабочего и изменение тайлов проверены по коду оригинала; после вырубки рабочий ищет следующий участок. Рубка использует исходные кадры и момент удара, проверенные на последовательности до готовности груза. [Анимация рабочего](docs/worker-strike-animation.md). Выбор лесопилки, вход и передача груза также [проверены по оригинальному коду](docs/worker-delivery.md); при размещении вход отмечен жёлтой точкой. [Автомат подхода](docs/worker-approach.md) управляет поворотом и повторными попытками при занятом входе; после потери лесопилки рабочий сохраняет груз и выбирает другую. [Доказательства и ограничения](docs/native-forestry.md). [Строительство шахты](docs/mine-deposits.md) и [добыча руды](docs/ore-extraction.md) подключены: ПКМ рабочими по своей шахте — мешки золота или металла носятся в замок (+100 за мешок). Дань, полный бунт, ремонт, переходы мира и сохранения ещё не подключены. Исследовательская лаборатория с прежней пошаговой демонстрацией доступна по **F10**.


Разбор устройства оригинала: [карта игровых систем и состояний](docs/game-logic-map.md), [индекс 123 шаблонов и 111 входов WRK](docs/logic-handlers.md). Здесь видны подтверждённые правила, пробелы и порядок переноса целых игровых циклов. [База ассемблера и статусы разбора](docs/assembly-database.md), [текущее покрытие](docs/assembly-progress.md). Для работы в новой сессии есть [краткая памятка](docs/continuation.md).

## Запуск на Windows 11

Готовые ресурсы текущего прототипа включены в репозиторий: `assets/imported` содержит первую карту, изображения, шаблоны, сценарий и статические наблюдения. **ISO, Python, WSL и команда импорта для запуска не нужны.** Набор занимает около 3 МБ и скачивается обычным Git или ZIP без Git LFS.

1. Установите **Godot 4.7.2 .NET** и **.NET SDK 10 LTS**. Нужен именно SDK, а не только Runtime; обычная Standard-сборка Godot не запускает C#.
2. Скачайте репозиторий через **Code → Download ZIP** и распакуйте целиком либо обновите свою копию ветки `main`.
3. В Godot выберите **Import**, укажите `project.godot` и откройте проект. Дождитесь автоматической подготовки изображений редактором.
4. Выполните **Build** для сборки C# и нажмите **F5**.

Кнопка Import в Godot открывает существующий проект. Подготовку PNG редактор выполняет автоматически; отдельная конвертация из ISO не требуется. При первом Build может понадобиться интернет для загрузки Godot.NET.Sdk через NuGet.

Запуск из терминала, если он удобнее:

```bash
git clone https://github.com/AlexandrVolkov/northwind.git
cd northwind
dotnet build
godot --headless --editor --path . --quit-after 120
godot --path .
```

`godot --version` должен показывать `4.7.2.stable.mono...`; `dotnet --version` — SDK 10. Если редактор не запускается этой командой, используйте полный путь к установленной .NET-сборке Godot. Папка `.godot` создаётся локально и в Git не хранится.

## Необязательное обновление ресурсов

Этот раздел нужен для работы с другой картой или разработки конвертеров. Готовый набор в репозитории содержит данные импортёра 11 для карты 1 и подготовленный атлас кадров схватки; его хватает для текущих сцен и режимов просмотра. Он не содержит все оригинальные карты, звуки и видеоролики игры. Оригинальный ISO, установщик и EXE в репозиторий не включены.

Если игра уже установлена/распакована, установите Python 3.10+ и зависимости, затем укажите папку с `NORWIND.EXE`, `MAP_1.MAP`, `MAPSEG01.SEG` и `ARMY__01.SPR`:

```bash
python -m pip install -r tools/requirements.txt
python tools/import_game.py "/путь/к/папке/игры"
```

Для импорта непосредственно из `Horde.ISO` дополнительно нужен **unshield**, распаковщик старого InstallShield. В Debian/Ubuntu/WSL: `sudo apt install unshield`; в macOS: `brew install unshield`.

```bash
python tools/import_game.py "/путь/к/Horde.ISO"
```

В Windows можно импортировать установленную папку игры напрямую. Для ISO через WSL установите Python, Pillow и unshield внутри WSL; путь к ISO выглядит как `/mnt/c/Users/.../Horde.ISO`.

Импорт перезаписывает отслеживаемые файлы `assets/imported`. Другую карту выбирайте через `--map 2`; возврат к набору из репозитория: `git restore assets/imported` (отменяет локальные изменения в этой папке). После обновления данных дождитесь их обработки редактором. Установщик и игровой EXE при конвертации не запускаются.

Все упоминания «повторите импорт» в описаниях этапов ниже относятся к обновлению старых локальных наборов. В свежей копии репозитория текущие данные уже подготовлены.

Бирюзовые кольца — ваши отряды, красные — противник. При атаке здания войско сначала вступает в бой с ближайшими защитниками. Раненые остаются ранеными; противник реагирует на приближение. После уничтожения замка добейте оставшихся защитников, их можно найти клавишей T. Баланс и команды миссии: [docs/playable-skirmish.md](docs/playable-skirmish.md).

## Первое хозяйство

Начальные запасы Олега берутся из SCN: **1000 металла, 1000 дерева, 1000 золота, 0 свободных людей**. Выберите замок (**C**) и постройте **ферму (30 дерева, 50 золота)**. Дождитесь прироста людей и наймите **рабочего (5 металла, 40 золота, 1 человек)**. **Лесопилка стоит 30 металла, 50 дерева, 80 золота и 2 человека**: дождитесь ещё двух свободных людей, затем разместите её ЛКМ по зелёной рамке. ПКМ/Esc отменяет размещение. Подсказки кнопок показывают недостающие ресурсы.

Рабочим укажите лес через ПКМ: он рубит и автоматически носит груз в готовую лесопилку. Запас растёт по 10 после обработки, не в момент рубки. Если лесопилки ещё нет, рабочий сохраняет груз. После вырубки участка он ищет следующий. [Исходные запасы и цены](docs/scenario-resources.md), [древесный цикл](docs/wood-economy.md), [фермы и население](docs/population-farms.md). Цены восстановлены из DAT. [Очередь найма](docs/recruitment-production.md) вмещает пять заказов: оплата при начале подготовки, ожидание свободного выхода, очистка с исходной формулой возврата. Готового юнита нужно увести с отмеченного выхода. Для ополченцев постройте казарму (50 металла, 80 дерева, 150 золота, 2 человека), дождитесь завершения и выберите её. Казарма имеет отдельную очередь и выход. Добыча металла и золота ещё не подключена.

## Что менять для модификаций

- **Баланс схватки, частота тактов и выбранные поселения:** `data/skirmish.json`. Это экспериментальные настройки, не таблицы оригинальных боевых правил.
- **Логика схватки / интерфейс:** `scripts/Skirmish.cs`, `scripts/SkirmishMain.cs`, `scenes/skirmish.tscn`.
- **Баланс и начальные отряды старой демонстрации:** `data/prototype_rules.json`. Здоровье, урон, ответный урон, запас движения, стоимость леса, координаты и состав демонстрационной схватки.
- **Правила и ИИ:** `scripts/Simulation.cs`. Не зависит от интерфейса и проверяется отдельно.
- **Отрисовка, камера, интерфейс:** `scripts/Main.cs` и `scenes/main.tscn`.
- **Конвертация ресурсов:** `tools/import_game.py`.
- **Другая оригинальная карта:** повторите импорт с `--map 2` (в образе найдены номера 1–10, 21, 22). Начальная позиция остаётся демонстрационной и при необходимости меняется в JSON.

Поля оригинального формата, смысл которых пока не установлен, сохраняются без переинтерпретации. Описание подтверждённых форматов и предположений: [docs/formats.md](docs/formats.md). Дальнейшее восстановление: [docs/reconstruction.md](docs/reconstruction.md).

## План полного переноса и исследование сценариев

[Полный план переноса](docs/port-plan.md) содержит этапы, зависимости, критерии готовности и текущие блокеры. Первый начатый этап расширяет импорт исходных сценариев; он не заменяет демонстрационные отряды реальными объектами до расшифровки OBE.

После повторного импорта **I** или кнопка **«Данные сценария»** показывают оригинальные имена участников/поселений и ссылки на файлы объектов выбранного сценария. Полный структурный каталог образа можно получить без конвертации изображений:

```bash
python tools/import_game.py "/путь/к/Horde.ISO" --audit
# Или из распакованной папки:
python tools/import_game.py "/путь/к/игре" --audit
```

Отчёт: `assets/imported/catalog.json`. В предоставленном образе проверены все 12 сценариев. Размер OBE в отчёте — число байтов, не число объектов.

## Запуск оригинала для сравнения

Блокер CD-ROM устранён: пустой файл `CD` из установщика нужно настроить буквой привода, на котором подключён ISO. [Диагноз и инструкция](docs/original-launch.md). `tools/prepare_dosbox.py` создаёт отдельную рабочую копию с конфигурацией DOSBox и манифестом хэшей, не меняя EXE и исходную установку. Подтверждены игровое поле и визуальный прогон движения; бой и внутренняя временная модель ещё требуют проверки.

## C# и .NET

Симуляция — `scripts/Simulation.cs`, типизированные JSON-модели — `scripts/GameData.cs`, интерфейс — `scripts/Main.cs`. Проект использует `Godot.NET.Sdk/4.7.2`, `net10.0` и SDK 10.x согласно `global.json`. При первой сборке NuGet загружает зависимости; файлы сборки и кэш в Git не входят.

C#-проверки запускаются внутри Godot .NET, поскольку поиск пути и координаты используют Godot API. Это не отдельный чистый .NET-пакет симуляции. Graphify теперь может индексировать C#-исходники локально, но полнота графа и экономия токенов отдельно не гарантируются.

## Просмотр записей объектов OBE

Повторите импорт обновлённым `tools/import_game.py`, затем нажмите **O** или кнопку «Исходные объекты». На карте и миникарте появятся маркеры исходных пар координат. **N** — следующая запись с фокусировкой камеры; панель показывает имя файла, байтовое смещение, длину и необработанные поля. **O** возвращает демонстрационный бой.

Координаты и коды пока требуют подтверждения в оригинале; масштаб 1:1 — проверяемая гипотеза. Маркеры не обозначаются как конкретные юниты и не участвуют в бою. `--audit` теперь считает записи OBE по цепочке длин: на предоставленном образе 2002 записи в 97 файлах. Размер файла в байтах по-прежнему хранится отдельно.

Просмотр OBE теперь показывает исходное название шаблона и ссылку на DAT. После повторного импорта создаётся `templates.json` с 123 шаблонами и исходными записями. Индексы OBE проверяются через таблицу армий SCN; неиспользуемые и неизвестные поля сохраняются. Название шаблона не означает, что его правила и анимации уже перенесены.

## Галерея для сравнения с оригиналом

После повторного импорта и обновления ресурсов редактором **P** открывает галерею шаблонов. Показаны кадры-кандидаты с исходным номером и размером; неустановленные изображения явно отмечены. На предоставленном образе: 72 кандидата, 51 не установлен. Это ещё не восстановленные анимации и не точная отрисовка исходных объектов.

Оригинал теперь доведён до игрового поля: на экране новой игры введите существующего персонажа **Олег**, затем Enter и «Старт». [Инструкция и эталон](docs/original-launch.md).

Для проверки камеры по собственному снимку DOSBox без масштабирования:

```bash
python tools/match_reference.py --game "/путь/к/игре" --screenshot field.png --viewport 336 216 448 448 --patch 164 34 --patch 264 84 --patch 344 334 --patch 64 84
```

Координаты viewport и участков приведены для исследовательского снимка 1280×800; для другого расположения окна укажите свои. Проверяется только точное совпадение ландшафта, не объектов.

## Первый объект и движение оригинала

Получено точное совпадение ополченца с кадром 71 и таблицей цветов COLOR_02.TAB, записана серия движения по правому клику. [Результаты и инструменты проверки](docs/object-reference.md). Привязка записи OBE к якорю пока остаётся гипотезой; игровая симуляция Godot этим этапом не изменяется.

Правила кампании, экономики, управления и состояний зданий со слов опытного игрока собраны в [заметках для восстановления](docs/player-gameplay-notes.md). Там отдельно отмечены неуверенные воспоминания и вопросы для проверки в оригинале.

Загрузчик DAT/WRK и ограниченный расчёт кадров замка теперь проверяются по исполняемому коду: [анализ EXE и воспроизводимые x86-проверки](docs/executable-analysis.md). Импортёр 7 исправляет двухбайтовый сдвиг границ DAT; повторите импорт для обновления `templates.json` до версии 2. Полные правила ремонта и строительства пока не перенесены.

Отдельный C#-модуль `OriginalBuildingRules` уже содержит две операции из оригинала: общий шаг увеличения состояния со списанием запасов и применение повреждения отдельной цели. [Сверка с x86 на 199 680 комбинациях](docs/building-condition-kernel.md) входит в тесты симуляции и не требует оригинальных ресурсов. Связь с командами, время и полный цикл здания ещё восстанавливаются.

`OriginalBuildingLifecycle` добавляет очередь прямой команды и начальные поля свежего замка, проверенные на 6348 комбинациях против EXE/WRK. Импортёр 8 сохраняет 233 описания кнопок, включая «Ремонт», и начальные параметры DAT в `templates.json` версии 3. Повторите импорт. ## Подтверждённые области в Godot

Повторите импорт обновлённым конвертером, дождитесь обновления ресурсов редактором, затем нажмите **B** или «Эталоны наблюдений». Доступны два независимых статических наблюдения: ополченец (280 непрозрачных пикселей) и корпус замка (10 697 пикселей; область флагштока исключена). Изображения собираются из оригинальных MAP/SEG/SPR/PAL/TAB, а не из снимков экрана.

Это отдельные наблюдения, сделанные в разное время; они не образуют полную игровую сцену. Универсальные якоря, анимация флага и оригинальные правила ещё не восстановлены. На другой карте или при несовпадении SHA-256 исходных ресурсов эталоны отключаются. [Доказательства и воспроизведение](docs/castle-reference.md).

`OriginalOccupancyMap` добавляет изменяемые три плоскости и проверенную начальную регистрацию всех 12 сценариев. **39 840** сравнений с x86 и проверка полных сеток связывают её с проверкой строительства. Импортёр **10** создаёт `scenario.json` версии **2**; повторите импорт. Полный такт, движение и видимость ещё не перенесены. [Правила регистрации и ограничения](docs/original-occupancy.md).

`OriginalSpatialRules` переносит фазу движения с обновлением занятости в середине клетки и отсоединение записи без уплотнения пула. **130 108** сравнений с x86; проверена связка с исходными лучником и замком первой карты. Планирование пути, анимация/эффекты и полный такт ещё не перенесены; управление демонстрационными юнитами остаётся экспериментальным. [Границы реализации и воспроизведение](docs/spatial-movement-removal.md).

`OriginalMotionPreparation` переносит выбор направления к точке, поворот на один сектор и чтение параметров движения из DAT/SEG, включая продолжение в уже перенесённый шаг. **283 201** сравнение с x86; подтверждена связка на лучнике первой карты. [Проверки и ограничения](docs/motion-preparation.md). Ресурсы уже включены в Git, повторный импорт не нужен. Поиск пути и полный игровой такт ещё восстанавливаются.

[Доказательства и границы](docs/native-route-search.md).
