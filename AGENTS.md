# Работа над Northwind

- Цель — **полная копия оригинальной игры** (вся кампания, системы, интерфейс, музыка и звук) для последующих модификаций и исправления ошибок оригинала, а не демо. Схватка — проверочная площадка для восстановленных систем. Переносите целыми игровыми циклами, по возможности крупными подсистемами за срез.

- Целевая версия движка — **Godot 4.7.2 stable, .NET / C#**. Точная версия записана в `.godot-version`; это метаданные проекта, а не механизм автоматической установки движка.
- Пишите и проверяйте изменения под этой версией. Перед проверками вызовите `<godot> --version`; если команда `godot` указывает на другую версию, используйте полный путь к 4.7.2. Не меняйте целевую версию без запроса пользователя.
- В `project.godot` тег `config/features` задаёт ветку API `4.7`, а не номер исправления `4.7.2`. Рендерер проекта — GL Compatibility.
- Код игры и интерфейса пишите на C#. Данные конфигурации остаются в JSON, конвертеры ресурсов — на Python. GDScript-версии удалены, не создавайте параллельную реализацию.
- Нужны .NET SDK 10 LTS (см. global.json), Godot.NET.Sdk 4.7.2 и **.NET-редактор** Godot. Standard-редактор не запускает C#-проект.
- Для C#-изменений: `dotnet build`, затем `<godot-dotnet> --headless --path . tests/TestRunner.tscn -- simulation`. С импортированными ресурсами также выполните `<godot-dotnet> --headless --path . tests/TestRunner.tscn -- scene`; графические изменения проверяйте с графическим рендерером.
- Для изменений конвертеров: `python -m unittest discover -s tests -p 'test_*.py'`.
- Оригинальные ISO, EXE и установочные архивы не добавляются в Git. По запросу пользователя готовый набор PNG/JSON для первой карты хранится в assets/imported вместе с метаданными .png.import: запуск из Git/ZIP не требует ISO или Python. При изменении конвертеров обновляйте этот набор и проверяйте сцену из чистой копии проекта; импорт другой карты меняет отслеживаемые файлы.
- Демонстрационные правила не выдавайте за восстановленные. Сохраняйте неизвестные поля и фиксируйте доказательства в docs/.
- Вопросы к автору ведутся в `docs/questions.md`; перечитывайте ответы в начале каждого среза и переносите отвеченные в «Закрытые».
- Для продолжения после смены сессии начните с `docs/continuation.md`: там зафиксированы текущее состояние, следующий исследовательский срез и команды проверки.
- В облачной сессии готовые Godot 4.7.2 .NET и Ghidra 12.2 восстанавливаются из ветки `toolchain` (`install.sh`, около минуты) вместо сборки из исходников.
