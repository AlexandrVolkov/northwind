# Звуковые банки оригинала

Девять банков FX разобраны и выгружены без потерь в `assets/imported/sound/`:
**100 номеров звуков, 166 вариантов, 11025 Гц, 8 бит, моно, unsigned PCM**.
WAV и JSON уже лежат в Git; ISO и Python для их использования на Windows не нужны.
Номера звуков и вариантов начинаются с нуля. Случайный вариант — часть формата,
его нельзя заменять последовательным перебором либо равномерным `% count`.

Это подготовленные ресурсы и отдельно проверенные правила. Автоматическое
воспроизведение игровых событий ещё не подключено: интерфейс и сцены игры
закреплены за Claude в очереди C1. Акустическая узнаваемость всех записей
человеком пока не проверена; назначение, не прослеженное до обработчика,
не определяется по одному имени банка.

## Доказательства в оригинальном коде

Адреса — смещения LE:1 `NORWIND.EXE`, SHA-256
`eb52f043143d763f5a595ae2175249976f278d1eebf0336ae032caf7bfa0c3a8`.

| Адрес | Что установлено |
|---|---|
| `13301`, `1337A`, `133F3` | Три пути настройки драйвера пишут слово `2B11h` (11025) в дескриптор `+3F`. Первые два включают стереовыход `+3D=1`, третий — моно. Это формат выхода микшера; записи FX остаются моно. |
| `13479`, `13643..13655` | Частота из `+3F` используется для размера буфера и передаётся драйверу командой `0401h`. Видео временно меняет частоту в `159F9`, затем `15A1D` восстанавливает обычный профиль; частота SMK не задаёт частоту FX. |
| `1416B..141B4` | Проверка включения звука `[9091]`, номера против `u16[bank]`, внешний индекс, пропуск длины группы, случайный байт `9E69`, умножение на байт количества вариантов, внутренний индекс, чтение размера и указателя PCM. Выбор: `(random_byte * variant_count) >> 8`. |
| `1414D..1416A` | Подсчёт активных каналов с тем же **текущим** указателем PCM. При числе больше 1 новый запуск пропускается. Это не общий запрет на повтор одного номера звука. |
| `14133..1414C`, `141B5..14200` | Поиск первого свободного из 255 каналов шагом `20h`. Длина маскируется `00FFFFFFh`, старший байт отдельно сохраняется в канале `+1F`; поля `+06/+0E` — начальный/текущий указатели, `+02/+0A` — длины, `+12/+16` — координаты, `+01` — счётчик повторов из BH, `+1A` — режим из BL, `+1B` — номер звука. |
| `1405B..140DA` | Предобработка банка: средний уровень вычисляется по всем PCM-байтам и записывается **перед PCM**, в старший байт слова длины. Данные звука не меняются. `140B0` восстанавливает ESI перед возвратом, поэтому `dec esi; mov [esi],al` в `14098` не портит последний отсчёт. Это кэш уровня, а не признак сжатия. |
| `14851..14872` | Предобработка банков армий (`descriptor+11`) и фонового банка `[6BF9]`. В файлах всех 166 записей исходный старший байт равен нулю. |
| `13F50..13F91`, `142E7` | Отсчёты без знака, тишина `80h`; масштабирование: `clamp(128 + trunc((sample-128)*gain/128), 0, 255)`. Буфер заполняется `80808080h`. |
| `1433D..14469` | Моно PCM читается по одному байту и подмешивается отдельно в левый/правый выход, шаг выхода 2. При конце BH=1 завершает канал, BH=0 возвращает его к началу бесконечно, BH>1 уменьшается. |
| `A416..A443` | Звук объекта: нулевой номер пропускается, банк берётся из дескриптора армии `+11`, координаты OBE `+04/+08` делятся на 32, BX=`0100h` (однократно, с позицией). |
| `A47E..A4A8` | Звук эффекта: армия из `effect+01`, координаты `+07/+0C`, BX=`0100h`. В отличие от A416, номер 0 здесь допустим. |
| `A4A9..A4C1`, `A4C2..A4DE` | Общий банк `[191E]` (WORK.FX): первый обёрточный вызов пропускает номер 0 и ставит BX=`0101h` (один раз, без позиции); второй использует координаты команды/отряда `+20/+21` и BX=`0100h`. |
| `3B9E..3BEF` | WORK.FX загружается в память после буфера спрайтов, адрес сохраняется в `[191E]`. |
| `14771..14801` | Отдельный фоновый банк загружается из имени `[6BC6]` в `[6BF9]`; вызовы `148DD..14956` запускают номера 3, 1, 0, 4, 5, 2 с BX=3 (BH=0, BL=3), то есть циклические фоновые каналы. Детали — задача C2. |

Старший байт слова длины сохранён как `raw_high_byte`, само слово —
`raw_size_word`. Дополнительно вычислен `mean_level` по оригинальной формуле:
`sum((b if b >= 128 else b ^ 255) & 127) // length`. Она симметрична между
127 и 128, а не обычное `abs(b-128)`. Не следует применять её как нормализацию WAV.
Формат WAV хранит ровно исходные PCM-байты; нет ресэмплинга, обрезки тишины,
изменения громкости или автоматического зацикливания каждого файла.
Сопутствующие `.wav.import` принудительно задают `compress/mode=0`: стандартный
импорт Godot 4.7.2 выбирает QOA со сжатием с потерями. Также выключены trim,
normalize и resample. UID и пути импорта, заполненные редактором, сохраняются.
Для нечётного числа PCM-байтов WAV содержит отдельный нулевой байт выравнивания
RIFF; в длину data и хеш PCM он не входит. Без него импортёр Godot пытается
перейти за конец файла. Длина RIFF включает этот байт.

## Формат файла

Все числа little-endian. Внешняя таблица:

| Поле | Размер |
|---|---|
| Число номеров звуков N | u16 |
| N абсолютных смещений групп от начала файла | N × u32 |
| Группы | до конца файла |

По каждому внешнему смещению лежит `u32 group_length`, за ним тело группы:

| Поле | Размер |
|---|---|
| Число вариантов K | u16, в оригинальном выборе используется младший байт |
| K смещений **от начала тела группы**, после `group_length` | K × u32 |
| Записи вариантов | до конца группы |

Запись варианта: `u32 size_word`, затем `(size_word & 00FFFFFFh)` байтов PCM.
Таблицы и записи непрерывны. Конвертер проверяет каждую границу, внешний размер
группы, внутренние размеры, порядок смещений и отсутствие лишних байтов.

| Банк | Номеров | Вариантов | Суммарная длительность |
|---|---:|---:|---:|
| WORK.FX | 20 | 24 | 73,24 с |
| MENU.FX | 6 | 6 | 76,42 с |
| MAP_1.FX | 6 | 6 | 124,51 с |
| ARMY__00.FX | 24 | 46 | 48,99 с |
| ARMY__01.FX | 8 | 23 | 76,43 с |
| ARMY__02.FX | 15 | 34 | 95,61 с |
| ARMY__03.FX | 11 | 17 | 60,78 с |
| ARMY__04.FX | 4 | 4 | 7,15 с |
| ARMY__05.FX | 6 | 6 | 15,08 с |

`manifest.json` содержит SHA-256 исходного банка, номера/смещения каждой записи,
число отсчётов, длительность, исходный старший байт и хеши PCM/WAV. Сырых FX и
байтовых распечаток в Git нет.

## Назначение, подтверждённое вызовами

| Событие | Запись | Доказательство |
|---|---|---|
| Выделение объекта/успешное выделение области | WORK.FX №4 | После записи `[1969]` и вызова перестройки панели `6A73` в `4AF8`, `4BA1` задаётся EAX=4 и вызывается A4A9. |
| Ранение | Банк армии, DAT dword `+A3` | `917E..9184`, если разность OBE `[1A]-[19]` ≥4. Для ополченца, лучника, рабочего и героя ARMY__02 — №1, всадника — №5. |
| Смерть юнита | Банк армии, DAT dword `+A7` | `95D3..95F6`. Для обычных воинов/рабочих/героя ARMY__02 — №2, всадника — №6, катапульты/баллисты — №3. |
| Выстрел стрелы | ARMY__00.FX №2 | WRK:00 `5CC..5D3`, FS:35 → LE:1 A47E. Этот вызов уже записывается исходным oracle `verify_arrow.py`. |
| Попадание летящей стрелы | ARMY__00.FX №3 | WRK:00 `64E..653`, FS:35 → A47E. Условия попадания — `verify_arrow.py`. |
| Завершение определённой строительной анимации | Банк армии, DAT `+A3` | `DD6F..DD75`; не все здания имеют ненулевой номер. |

Голоса отсутствовали по ответу автора; WAV не переименованы в «реплики».
Полное сопоставление шагов, рубки, строительных работ и отдельных разрушений
с ветвями WRK ещё требует отдельной трассировки. DAT `+A7` — звук смерти,
его нельзя считать звуком выделения. Номер 0 допустим в самом банке и у эффектов,
но у некоторых обёрток означает «нет звука».

## Воспроизведение и проверка

Экспорт только для разработчика с извлечёнными файлами игры:

```sh
python tools/sound_source.py --game /path/to/Program_Executable_Files
python tools/verify_sound.py --game /path/to/Program_Executable_Files --fixture /tmp/sound.json
python -m unittest discover -s tests -p 'test_*.py'
```

`verify_sound.py` исполняет оригинальные инструкции под Unicorn:

- три пути настройки драйвера подтверждают 11025 Гц;
- 2048 синтетических выборов проверяют все случайные байты для 1, 2, 3, 4, 5, 7, 16, 255 вариантов;
- **25600** выборов на всех реальных банках совпадают по указателю PCM и слову длины с конвертером;
- **65536** пар отсчёт/громкость проверяют арифметику микшера;
- 28 случаев среднего уровня и целый синтетический банк проверяют запись кэша перед PCM без изменения самих отсчётов.

RNG `9E69` подменяется контролируемым байтом. IRQ/DMA, позиционное затухание,
смешение нескольких каналов, лимит каналов, повторы и весь звуковой планировщик
этой проверкой не покрыты. Фикстура хранит параметры и хеши результатов,
не машинный код. Неиспользуемые остатки регистров не сравниваются.

## Музыка

Задача C2 ещё не выполнена. Ответ автора исключает прежнее предположение о
недостающих CD-Audio дорожках: он помнит музыку при прокрутке истории и фон
в игре. Длинные записи MENU.FX/MAP_1.FX и их циклическое воспроизведение —
подтверждённые кандидаты, но «длинный звук» сам по себе не доказывает музыку.
