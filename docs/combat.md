# Бой: удар, урон, жизненные показатели

Урон, здоровье и темп ударов в схватке теперь исходные: здоровье — байт OBE[19] записи (ополченец 10, предводитель 50, замок 127), максимум — OBE[1A], урон — формула BFC9 с защитой DAT[44], удар наносится анимацией в исходный момент. Временные `health`/`damage`/`cooldown` из `data/skirmish.json` для расчёта больше не используются. Выбор цели, ИИ и полёт снарядов пока временные.

Адреса — LE:1 и `ARMY__00.WRK` (общий набор эффектов).

## Как наносится удар

1. Анимация атаки (945E) в момент удара создаёт **объект-эффект** (9727) типа DAT[70] атакующего в точке перед ним: координаты + знаковые смещения DAT[60..6F] по направлению. Бит 7 типа означает набор армии 0; у ополченца, рыцаря, предводителя и всадника это 128 → армия 0, тип 0.
2. Таблица типов эффектов — хвост файла DAT после шаблонов, записи по 7 байт: ширина, высота, смещение обработчика в WRK (u32), флаг. Эффекты хранятся в массиве `[6B2]` записями по 22h байта и обновляются циклом 96CD.
3. Эффект «удар» (`ARMY__00.WRK 4F3`, AH=0):
   - **атака = 5 + ((OBE[16] + 1) >> 6)** — растёт с опытом атакующего (байт +16, 0…127, т.е. 5…7);
   - 982B ищет объект в клетке точки удара в плоскости эффекта, с проверкой попадания в область DAT[3]/[4]; объекты с DAT.flags & 8000 не поражаются. **Владелец не проверяется** — удар по своему, оказавшемуся в точке, тоже проходит;
   - BFC9 наносит урон; при успехе играется звук 0 (или 1 для целей с DAT.flags & 10) и эффект становится анимацией искр (тип 4/5, 8 кадров по 2 такта). Промах освобождает эффект.

Стрелы описаны ниже. Обработчик 762 (тип 6, `OriginalCombatRules.CellHitEffect`, сверка — режим `cellhit` в `tools/verify_combat.py`, 16000 случаев): 97C6 берёт объект в клетке точки (без проверки основания) и класс местности; атака как у удара (5 + (опыт+1)>>6), вид — команда нападающего & 7. Живой объект (вид не 3, состояние > 0) теряет атака − DAT[44] (байтовое вычитание: при результате с битом 7 — 0), в +17 пишется метка 1 (и 2 при уроне), звук 0Ch, искры как у удара (твёрдая цель, DAT[40] бит 4, — тип 5). Пустая клетка или промах на местности класса 1 — звук 0Dh и твёрдая искра, иначе эффект освобождается. Кто создаёт эффекты типа 6 в кампании — не прослежено.

## Формула урона, BFC9 (FS 119)

```text
если цель мертва (i8 OBE[19] ≤ 0) — нет попадания
OBE[17] = (OBE[17] & E0) | (вид << 3) | 1           ; отметка попадания
d = атака − DAT[44] цели                              ; защита
если атака > защиты (беззнаково): урон = d
иначе: k = u8(2 − d); если k > 4 — нет урона;
       иначе с вероятностью 1/k урон = 1               ; d=0 → 1/2, −1 → 1/3, −2 → 1/4
OBE[19] = max(OBE[19] − урон, 0); OBE[17] |= 2
```

Защита DAT[44]: ополченец/лучник/рабочий 0, рыцарь 2, предводитель и башни 3, здания 4. Ополченец (атака 5) убивает ополченца за 2 удара, рыцаря (5 − 2 = 3) — за 4, по зданию бьёт по 1.

## Жизненные показатели, 90E9

Общий префикс каждого юнита перед диспетчером действий (8227):

- OBE[19] ≤ 0 → путь смерти 95D3: звук гибели DAT[A7] (если ещё не «давно мёртв»), затем посмертная анимация A4DF; при DAT.flags & 100000 — особая ветвь 12D08.
- Живые (без DAT.flags & 10): **поглощение урона опытом** — `min(OBE[16] >> 5, OBE[1A] − OBE[19])`, где OBE[1A] — состояние на прошлом обновлении (его записывает 42BB после каждого обновления объекта). Ветеран (опыт ≥ 32) возвращает часть урона, полученного за последний такт; это не лечение до максимума. **Кровотечение**: при здоровье ≤ 2 с шансом 1/32 −1.
- В покое раз в 256 тактов **отдых**: +¼ здоровья, но не выше DAT[45].
- При здоровье ≤ 2 (не в действии 3) — **бегство** 8E0E в случайную клетку карты. Также бегство при OBE[17] & 1A = 1A.
- Потеря ≥ 4 за такт (OBE[1A] − OBE[19]) — звук ранения DAT[A3] (A416).
- Раз в 256 тактов с шансом 1/8 **опыт** растёт: `OBE[16] + 2 − (OBE[16] >> 6)`, при переполнении знака — 127.
- В покое: если DAT[58 + класс местности & 7] = 0 и в нижней плоскости нет опоры — гибель.

RNG: первый поток 9E41 (`[19EB]`), второй 9E55 (`[19EC]`), общая таблица 256 байт.

## Цикл атаки воина, 843E / 8EC7

Действие 3 воина (таблица WRK 0000 → FS F5 → 843E) в фазе 1 повторяет:

1. **8ABF** — жива ли цель OBE[1C]: состояние должно быть выше DAT[46] цели. У зданий это порог разрушения (замок 20): ниже него здание считается разрушенным, удары прекращаются. При гибели цели атакующий с опытом < 64 получает `DAT[76] цели / 4` опыта (ополченец 20 → +5, рыцарь 30 → +7, предводитель 96 → +24).
2. **8B5E** — досягаемость: «пробивная сила» DAT[71] атакующего должна превышать защиту цели (ополченец 5 > здание 4); плоскость цели — бит маски DAT[74]; расстояние `((зазор 9B86 + 15) >> 5) + 1` клеток — не больше DAT[72] (ополченец 1, лучник 7) и не меньше DAT[73] + 1; цель на воде (класс 1) дальше 48 px недосягаема. Слишком далеко — движение к клетке цели (8CBB), слишком близко или недопустимо — действие заканчивается.
3. **8AF4** — ворота удара: OBE[2F] растёт каждый такт до `DAT[75] − hi8(DAT[75] · опыт)` (ополченец 4, лучник 15 тактов; опытные бьют чаще).
4. **8BEA** — ожидание покоя и поворот к цели, затем **8C7C** — запрос удара (состояние 3, OBE[22]=FF — цель-объект).
5. Анимация удара (9210/93DF..9406 для цели-объекта: координаты цели в OBE[28]/[2A], слой в OBE[27]) на прогрессе DAT[4E] вызывает 945E: эффект DAT[70] в точке перед воином, сброс OBE[2F].

## Стрелы, эффект типа 2 (`ARMY__00.WRK 593`)

Лучник (DAT[70] = 130 → армия 0, тип 2) в момент удара создаёт стрелу в точке выстрела:

- **Прицел 9A1B**: точка цели (OBE[28]/[2A]) смещается случайно по обеим осям (два потока RNG). Разброс `d − hi4(d · (8 + опыт>>4))`, где `d = min(расстояние/2, 255)`: чем дальше и неопытнее стрелок, тем шире.
- **Скорость 996F**: 15 px за такт по главной оси (24.8, поля +18/+1C), вторая ось пропорционально; остаток пути в +12. **Направление A5B8** — 16 направлений, кадр `19h + 2·направление`.
- **Полёт 5DA**: каждый такт позиция +6/+0B сдвигается на скорость, остаток уменьшается; вне карты стрела исчезает. Над чужим объектом с DAT-флагом 8 (здания, ограды) стрела с вероятностью ½ попадает в него раньше.
- **Попадание**: на остатке ≤ 16 — объект в точке (982B). **Урон 4 − защита** без опыта и без случайного шанса: ополченец теряет 4 из 10, рыцарь — 2, здание — 0. Без урона стрела застревает (AEB) или падает (7FE); с уроном — искры (тип 4/5) и звук 3.

В схватке стрелы — настоящие объекты-эффекты (`Skirmish.Arrows`), обновляются каждый такт до юнитов. Обработчики упавших/застрявших стрел (7FE/AEB), Камни катапульт, болты баллист и огненные снаряды перенесены (ниже).

## Камни катапульт, эффект типа 8 (`ARMY__00.WRK 85A`)

Катапульта (DAT[70] = 88h → армия 0, тип 8) в момент удара создаёт камень. Таблица типов эффектов ARMY__00.DAT: тип 8 — 10×10, обработчик 85A; тип 10 — 128×128, 986 (взрыв). Перенос — `OriginalCatapultRules`, сверка — `tools/verify_catapult.py`, `tests/fixtures/catapult.json` (создание 252, полёт и попадание 3200, дым 15 случаев; режим `simulation`).

- **Запуск (AH=0):** владелец из стрелка, кадр BBh. Прицел 9A1B с точностью 1 (разброс почти на всё расстояние, стрелы — 8), скорость 996F — 9 px за такт (стрелы — 15). Звук 6.
- **Полёт D6E6:** пока остаток `+12` больше нуля, позиция 24.8 сдвигается на скорость. Остаток уменьшается на большую из составляющих: модуль берётся по флагу переноса сложения, так в оригинале. Высота `+10` растёт на `+20` (не ниже нуля), `+20` уменьшается на B9h. За краем карты эффект освобождается.
- **Падение (остаток ≤ 0):** BD0F бьёт клетку падения в плоскостях 0 и 1. Каждый объект учитывается один раз. У живого состояние уменьшается на `0Ah − DAT[44]`, если это больше нуля (не ниже 0); в младшие 5 бит `+17` пишется 11h, при ранении 13h. Атака от опыта не зависит, случайности нет.
- **Затем:** CFAC с AX=300h оставляет воронку (см. ниже), эффект становится взрывом (тип 10, кадр BCh, 18 кадров по 2 такта, звук 7).
- **Взрыв (9AE)** каждый такт смещается на общий вектор `[1C8E]/[1C92]` (через FS:[0C]). Вектор — ветер 9E7D (см. «Ветер»).

В схватке камни — `Skirmish.Stones`, обновляются вместе со стрелами. Катапульта (16) добавлена в правила схватки (экспериментальные значения) и в атлас кадров, противник может её нанять. На первой карте его ИИ её не заказывает: классы армий LE:3 F0E6 (E8, D8, FB, F9, F8) не дают класса A00h.

**Бегство во время замаха (адаптер).** 8E0E ставит запрос движения (старшая тетрада `+2D` = 2), в том числе посреди замаха (состояние 3). Оригинал доводит замах и начинает движение (9275 → 939A, не перенесено). В схватке боец с таким запросом выходит из боя, и его ведёт маршрут бегства. Раньше это давало исключение «Unsupported stationary worker state» в долгих боях. Баллиста (тип 1Dh, 12EC) и поджигатель (тип 11h, BAB) не перенесены.

## Болты баллист, эффект типа 1Dh (`ARMY__00.WRK 12EC`), большой взрыв 0Ch (A44)

Баллиста (DAT[70] = 9Dh → тип 1Dh). Перенос — `OriginalCatapultRules` (`CreateBolt`, `StepBolt`, `CreateBigExplosion`), сверка — `tools/verify_catapult.py` (запуск 96, полёт и падение 360, взрыв 8 случаев).

- **Запуск:** кадр 226h + направление, прицел 9A1B с точностью 0, скорость 12; звука нет.
- **Полёт** — D6E6, как у камня.
- **Падение:**
  - пять попыток бросить огненный снаряд (тип 11h) из точки болта к точке в пределах ±64: Y — по 9E55, X — по 9E41, точка дальше размера карты пропускается. Снаряд создаётся без стрелка, ему передаётся владелец болта;
  - удар по клетке BD0F: атака 0Ah, вид 3 — флаги 19h или 1Bh (бегство у раненых);
  - большой взрыв (тип 0Ch, 128×128, кадр 85h, 18 кадров по 2 такта, звук 9).

В схватке баллиста (26) есть в правилах (экспериментальные значения) и в атласе. Противник на первой карте её не заказывает, как и катапульту.

## Огненные снаряды, эффект типа 11h (`ARMY__00.WRK BAB`)

Поджигатель (DAT[70] = 91h → армия 0, тип 11h) стреляет огнём. Баллиста при падении болта рассыпает пять таких снарядов. Перенос — `OriginalFireRules`, сверка — `tools/verify_fire.py`, `tests/fixtures/fire.json` (создание 432, полёт 1728, дым 16 случаев).

- **Запуск (AH=0):** кадр 19h. Со стрелком — его владелец и прицел 9A1B с точностью 2. Без стрелка (снаряд, рождённый 9727 из болта баллисты) — летит прямо в точку. Скорость 15, направление A5B8 прибавляется к кадру дважды. Звук 4.
- **Каждый такт полёта (AH=1):**
  - 9727 ставит за снарядом дым (тип 12h, армия `+1`, слой 1);
  - если 982B находит в точке чужое здание (DAT[40] бит 8, владелец не равен `+2`), при бите 0 случайного числа 9E41 оно загорается;
  - иначе полёт D6E6.
- **Падение:**
  - **на объект:** при живом объекте — урон `4 − DAT[44]` (без опыта), флаги `+17` 09h или 0Bh. Затем при `9E41 · DAT[44] ≥ 256` огонь отражён (FA4, тип 16h), иначе объект загорается;
  - **на пустую клетку:** загорается только лес (класс местности 1), иначе снаряд исчезает;
  - загорание — звук 5, эффект переходит в огонь CE3 (типы 13h–15h).
- **Дым (C8A):** 11 кадров по 3 такта, поднимается (`+20` = 1F4h, тормозит на 30h за такт), сносится общим вектором FS:[0C].

В схватке снаряд летит и бьёт по-настоящему (`Skirmish.Stones`). Огонь CE3 и отражение FA4 ещё не перенесены, поэтому загорание пока заканчивает снаряд.

В схватке снаряд летит и бьёт, загорание превращает его в огонь, отражение — в искры.

## Огонь, эффекты 13h–15h (`ARMY__00.WRK CE3`), искры 16h (FA4), столб дыма 0Bh (9D5)

Перенос — `OriginalBurnRules`, сверка — `tools/verify_burn.py`, `tests/fixtures/burn.json`: 6000 случайных случаев, всё совпадает. Настоящие 982B, 97C6, 68BD и обработчики WRK; 9727, звуки и CFAC — заглушки с записью. Байты `+6` и `+0B` записи (дробные части координат) огонь использует как таймер роста и счётчик кадров.

- **Загорание (AH=0):** малый огонь (13h, 26×32), кадр CEh, высота 5, звук 8. Привязка зависит от того, что под точкой:
  - объект (982B; кроме DAT[40] бит 4000h) — `+18` = ссылка на него. Здание (`+17 = 2`): огонь поднимается к его верху на половину разницы с `DAT[2] + y`. Боец (`+17 = 0`): огонь у его ног;
  - лес (класс 1) — `+17 = FFh`, `+1E = FFh`;
  - иначе эффект исчезает.
- **Каждый такт:** объект получает флаги `+17 |= 1Fh`; огонь у бойца следует за ним; мёртвый объект отвязывается.
  - **Разгорание:** сначала `+0B` идёт от 36h до 19h, затем запоминается состояние объекта и его кадр.
  - **Кадры** крутятся по 25; раз в 16 тактов звук 8. Средний и большой огонь раз в 16 тактов выбрасывают искры (16h, на 15 точек ниже).
  - **Горение объекта:** раз в `2^(15h − тип + +17)` тактов состояние −1. Ремонт (состояние выросло) или гибель гасит огонь на ступень. Здание, дошедшее до кадров развалин (`DAT[48] + (DAT[4A] + DAT[4B])`), снижает пламя на 3.
  - **Лес:** раз в 16 отсчётов `+1E` объект в клетке (97C6) теряет 5; вне леса огонь гаснет. Когда `+1E` кончается, клетка выжигается (CFAC), и огонь гаснет на ступень.
  - **Рост:** когда `+6` доходит до нуля (раз в 90 тактов), огонь растёт: 13h → 14h сразу; 14h → 15h только при ветре — общий вектор / 16 не меньше 20h. При этом рождается новый огонь в точке, сдвинутой на ветер. Высота +10 за ступень.
  - **Угасание:** ступень вниз (высота −10); малый огонь становится столбом дыма (0Bh: 14 кадров по 2 такта, подъём 300h, снос ветром).

В схватке огонь живёт в `Skirmish.Stones`. Выжженная земля — CFAC с AX=101h (см. ниже). Звуки не воспроизводятся. Ветер перенесён (ниже). Проверка моста — `SkirmishFireChecks` (режим `skirmish`): огненный снаряд поджигает замок и тот теряет состояние.

## Ветер, 9E7D

Таймерный такт 9BF9 увеличивает байт `[19E8]` и, пока игра идёт, вызывает 9E7D. Перенос — `OriginalWindRules`, сверка — `tools/verify_wind.py`, `tests/fixtures/wind.json` (1440 случаев).

- Вектор `[1C8E]/[1C92]` прибавляет ускорение `[1C97]/[1C9B]`, каждая ось в пределах ±1000.
- Направление ветра (16 румбов, `[1C96]`) пересчитывается тем же способом, что у стрел (A5B8). Делитель — второй байт большей составляющей; при нуле направление не меняется.
- Когда `[19E8] = 0` (раз в 256 тактов), новое ускорение по каждой оси: `±(случайное & 3)`, знак — бит 7. Ось X — 9E41, ось Y — 9E55.
- Ветер сносит дым, взрывы и столбы дыма (через FS:[0C]) и управляет огнём: средний огонь растёт и перекидывается, если вектор / 16 не меньше 20h.

В схватке ветер обновляется каждый игровой такт (`Skirmish.Wind`).

## Воронки и выжженная земля, CFAC

CFAC меняет тайлы клетки (здесь область 1×1).

- **AL = 0, воронка** (катапульта, AX = 300h). Клетка, у которой все четыре угловых кода равны, получает случайную поверхность с теми же углами и подтипом AH = 3 (CE9D), затем вписывается в соседей (CD72). Неоднородная клетка не меняется.
- **AL ≠ 0, расчистка** — тот же путь, что у лесоруба (AX = 201h, подтип 2 — расчищенная земля, [native-forestry.md](native-forestry.md)). У огня AX = 101h, подтип 1 — выжженная земля. Якоря перебираются среди поверхностей нужного подтипа.

Перенос — `OriginalTerrainCatalog.Crater` и `Scorch` (`ClearTimber` = `Scorch` с подтипом 2). Сверка — набор `scorch` в `tools/verify_forestry.py` (1536 случаев), режим `original-forestry`. В схватке катапульта оставляет воронки, а огонь выжигает лес.

## Смерть, 95D3 / A4DF

- **95D3**: при DAT-флаге 100000h — особая ветвь 12D08 (не перенесена); иначе, если состояние ещё ≥ −12 и нет флага 80h в OBE[17], звучит звук гибели DAT[A7], затем A4DF.
- **A4DF, первый шаг** (состояние ≥ −12): юнит, застигнутый посреди шага, «досаживается» в клетку (9A8E), его область занятости очищается (43B0). Вид последнего удара (OBE[17] биты 3–4, ставится BFC9 и стрелой) выбирает набор кадров DAT[4F..52]; если набор пуст — набор 0. Кадр: `DAT[48] + 8·(DAT[4A]+DAT[4B]) + 4·(сумма предыдущих наборов) + (направление>>1)·длина набора`. Состояние становится `F0h + вид` (−16…−13), счётчик OBE[15] — длина набора.
- **Дальше**: на чётных OBE[2E] счётчик уменьшается и кадр растёт; в конце, если под юнитом не вода (класс 1/2), создаётся объект-труп DAT[53 + вид] (9727), затем объект удаляется (98DB).

В схватке павшие остаются на поле до конца анимации (`Dying`), затем исчезают; кадры удара и смерти добавлены в атлас (`tools/prepare_skirmish_frames.py`). Объект-труп и ветка 12D08 не перенесены.

## Трупы, эффект ARMY__02 типа 1 (`WRK:02 161D`), кровь ARMY__00 типа 3 (`WRK:00 6C7`)

Когда анимация смерти кончается не на лесе и не на воде, A4DF создаёт через 9727 эффект с кодом `DAT[53 + (+19 & 3)]` армии погибшего: у бойцов это 1, труп. Погибший передаётся обработчику в EBX, эффект лежит в плоскости 0. Перенос — `OriginalCorpseRules`, сверка — `tools/verify_corpse.py`, `tests/fixtures/corpse.json` (1755 + 32 случая).

- **Создание:** на воде (класс 2) труп исчезает, если под ним нет объекта с DAT[40] бит 2 (моста). Труп берёт кадр и владельца погибшего; вариант `+6` = (бит 4 флагов удара → 4) + направление / 2.
- **Кровь:** если смерть не от удара вида 3 (флаги 18h), рядом (−7…+8 по 9E41: младшая тетрада — X, старшая — Y) появляется брызг крови — тип 3 армии 0, кадр 72h. 11 кадров: первые по 5 тактов, последние шесть держатся по 220 тактов (пятно).
- **Разложение:** 4 стадии по 600 тактов; на первой труп переходит на кадры `235h + 3·вариант`. После четвёртой труп исчезает.

В схватке трупы и кровь — `Skirmish.Corpses`, рисуются условно (пятно), без исходных кадров. Другие коды трупов (здания: 10h–70h) не перенесены. Проверка — режим `skirmish-ai`: после боя на поле остаются трупы.

## Выбор цели, D895

Стоящий юнит в действии 0 (82C3 → 8D3E) раз в 8 обновлений (`OBE[2E] & 7 = 0`, счётчик увеличивает 8227) ищет врага; найденная цель записывается в OBE[1C] (8E3C), и тот же обработчик переходит к циклу атаки 8EC7. Идущий юнит (8273) отвечает только если по нему попали (OBE[17] бит 2): 8E81 ищет врага в радиусе атаки.

- **Радиус**: в покое — обзор DAT[47] (ополченец 3, лучник 6 клеток), +1 при опыте ≥ 40 у не-зданий; в движении — дальность атаки DAT[72]. Область — DAT[3]+2r × DAT[4]+2r вокруг клетки, обрезанная картой (219C3).
- **Кандидаты** (D7B1): уникальные объекты занятости области по строкам сверху вниз, слева направо, плоскости 0..2.
- **Фильтры**: не свой владелец (свои считаются отдельно), виден нашему владельцу (бит в OBE[20]), состояние выше DAT[46], установлен контакт с его поселением (иначе событие первой встречи EDD5), враждебен по маске участника +12 (или DAT-флаг 400000h), без флагов 8020h, плоскость в маске DAT[74], защита ниже пробивной силы DAT[71], не на воде дальше 48 px.
- **Выбор**: минимальное расстояние Чебышёва между центрами (C344); при равенстве — тот, кто сам целится в нас.

Видимость OBE[20] — маска владельцев, которым объект виден: при создании (A855, 8815) и у всех объектов сценария это FFh, скрываются только ловушки (DC91). В схватке используется маска из записи.

Маска вражды участника (+12) загружается из SCN +0F, контакты (+B9, 16 байт) — из SCN +3A (2EF1, 2F60). На первой карте у всех поселений обе нулевые: при первой встрече D895 вызывает EDD5, который ставит событие типа 3 в очередь сообщений участника (+34, 8 записей по 0Eh, обработчики по таблице 0EFBh). Ядро дипломатии перенесено ([diplomacy.md](diplomacy.md)): в схватке война начинается с объявления, контакт — с первой встречи.

## Хвост обновления объекта, 42BB

После обработчика AH=1 каждого объекта (434D..4384): `OBE[1A] = OBE[19]`; цель OBE[1C] забывается, если у неё флаг 200h в OBE[17] или отрицательное состояние; раз в 8 глобальных тактов в OBE[17] сбрасываются биты 0, 1, 2, 5 и 9 (отметки попадания, «по мне попали», толчок у входа). Обход — по участникам по порядку, внутри — по цепочке объектов в пуле. В схватке юниты обходятся по владельцу в порядке списка; здания пока обрабатываются отдельными проходами. Сверка: `tools/verify_update_tail.py`, 5 760 случаев.

## Подключение к схватке

`Skirmish.Strike` применяет BFC9 с исходной атакой; `TickVitals` выполняет 90E9 каждый такт (смерть убирает объект, бегство ведёт к случайной клетке через маршрут). `AttackStep` исполняет пункты 1–5, `ResolveImpact` — эффект удара в исходной точке (982B → BFC9), поэтому удар может задеть и того, кто оказался в точке удара. Мостами остаются: видимость/контакт/дипломатия в выборе цели, движение к цели маршрутом Godot, фазы 0/2 действия 843E (8CF3, 8F70), снаряды катапульт, баллист и поджигателей (попадание сразу по цели с исходной атакой), визуальные эффекты и звуки.

Мост схватки выставляет каждому идущему юниту состояние движения OBE[2D]=22 (как исходный код), поэтому правило гибели на местности проверяет только стоящих юнитов, а не промежуточные точки шага. Утонуть может юнит, остановившийся на воде без опоры (моста) в нижней плоскости.
