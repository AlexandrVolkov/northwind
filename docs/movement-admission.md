# Допуск движения по SEG/DAT и всей области юнита

В схватке проходимость теперь проверяет перенесённый код **7C63..7F33**: вся область юнита, выбранная плоскость занятости, байты SEG/DAT и наземные опорные объекты. Палитровая классификация остаётся данными лаборатории; допуск движения её больше не использует. Сам маршрут пока ищет Godot, исходные 7497/7FA7 ещё требуют переноса.

## Установлено по коду

Адреса — смещения кодового объекта LE известного NORWIND.EXE. `tools/verify_movement_admission.py` проверяет EXE через прежний анализатор и исполняет эти инструкции под Unicorn.

**7C63..7D44** выбирает DAT движущегося объекта, читает поле владельца **97A + owner × F5 + 12**, размеры DAT[3]/[4], слой `OBE[0D] & 3` и байт DAT[3F]. Из текущего центра вычисляется левый верхний угол области, затем прибавляется исходный шаг направления из таблицы **19C7**. Проверяется, что вся область помещается в карту. Вход **7D4C** использует тот же общий блок для кандидата планировщика. Поддерживаемый контракт переноса — байтовые ненулевые размеры карты и области, область не больше карты, слои 0..2, направления 0..7 и индексы владельцев 0..31. BT по памяти за первым u32 маски не включён в контракт.

**7DA5..7E75** проходит всю область по строкам, проверяя только выбранный слой:

- Для занятой клетки выбираются запись объекта и его DAT.
- Если бит владельца объекта присутствует в маске и байт DAT[3F] движущегося объекта превосходит чужой как минимум на 10, сохраняется код **3**, обработка этой клетки продолжается без остальных проверок занятости.
- Иначе объект с DAT.flags & 8 вызывает немедленный отказ.
- Для остальных записывается код **1**. При OBE[14] & 40 он сохраняется; иначе запрошенное состояние в старшем OBE[2D] должно быть 2, а OBE[24] не должно равняться 2. Нарушение даёт немедленный отказ.
- Если дополнительно `((чужой OBE[25] + 4) & 7) == направление`, код становится **2**.

Это не максимум кодов по области: более поздний контакт может заменить предыдущий результат. Порядок строк и ранний отказ сохранены. Маска и DAT[3F] оставлены полями без выдуманного назначения дипломатии/массы.

**7E76..7F18** отдельно проверяет каждый тайл области. Младшее слово u32 клетки MAP выбирает восьмибайтовое свойство SEG; используется его первый байт `p`. Читается `v = DAT[58 + (p & 0F)]`, то есть окно **16 байт**, а не только восемь классов. Затем:

```text
если v & 80: effective = v & 7F
иначе:      effective = u8(v - (p >> 3))
проход разрешён при i8(effective) > 0
```

Это проверка допуска, отличная от уже перенесённой подготовки скорости 7180, где используются другие маска/сдвиг. Поэтому простая проверка ненулевого DAT[58 + (p & 7)] недостаточна.

Если поверхность не разрешает движение, **7EAC..7F02** допускает замену только для слоя **1**: в нулевой плоскости той же клетки должен находиться объект с DAT.flags & 2, `i8(OBE[19]) > i8(DAT[46])` и его DAT[3F] не меньше соответствующего байта юнита. Эти условия выполняются у исправного моста из исходных DAT. Проверка не фильтрует объекты по названию «Мост»; другие записи с этим флагом подчиняются той же операции. Эффекты таких объектов и их полный жизненный цикл сюда не входят.

## Результат и вызывающая сторона

`OriginalMovementAdmission` возвращает исходный байтовый код и CF:

| Код | CF | Значение на этой границе |
| --- | --- | --- |
| 0 | 0 | Свободная область с допустимой поверхностью |
| 1/2/3 | 0 | Контакт требует дальнейшей обработки вызывающей стороной |
| FF | 0 | Край карты либо недопустимая поверхность без опоры |
| FF | 1 | Ранний отказ по занятому объекту |

После успешного обхода области исходный ZF разрешает кандидата планировщика и при кодах 1/2/3. Их обработка исполнения шага в **7FA7** ещё не перенесена; нельзя считать эти контакты свободным местом и просто пройти сквозь отряды.

Перед вызовом оригинал снимает свою область через **43B0**. Исследовательский прогон выполняет настоящий 43B0, затем 7C63. C# получает ту же картину без изменения карты: собственная ссылка игнорируется на активной плоскости. Проверка не меняет запись движущегося объекта.

## Подключение к прототипу

`Skirmish.CanStand` использует эту проверку, а не цвет тайла. Для ссылок доступны все исходные записи сценария; активные актёры подставляют актуальные запись и DAT, в том числе после загрузки/сдачи груза рабочего. Плоскость 0 с мостом больше не отвергается как препятствие для слоя 1. Поддержка читается на каждой клетке полной области.

Схватка пока принимает только код **0**, сохраняя обход всех занятых клеток активного слоя. Для этого консервативного правила задана маска 0: любой контакт всё равно даёт ненулевой результат. Восстановление исходного поля владельца и обработки контактов 1/2/3 остаётся отдельной задачей. Дополнительные резервы Godot теперь занимают **всю следующую область и её слой**, освобождаются по ссылке отряда. Групповые цели также выбираются без пересечения областей на одном слое. Строительство учитывает резерв любой из трёх плоскостей, как и прежде.

Клеточный драйвер прототипа ведёт подвижные объекты по центрам клеток (`cell × 32 + 16`); фабрика рабочих использует это размещение отдельно от паритетных якорей зданий. Тест увеличенного рабочего проверяет именно этот драйвер. Полный исходный диспетчер движения, размещение всех типов подвижных объектов, восемь направлений маршрутизатора, собственный упакованный пул путей и все стадии завершения шага ещё не подключены. Проверенные арифметические ядра движения не изменены. Частота, бой и игровой баланс остаются экспериментальными.

Новых карт, строительства мостов и их отдельного игрового интерфейса этот этап не добавляет. Восстановлено правило проходимости, необходимое для таких объектов и дальнейшего переноса карт.

## Проверки

Числовые ожидания снимаются с оригинальных инструкций, без модели результатов на Python:

| Область | Случаев |
| --- | ---: |
| Все 256 значений SEG-байта × 256 значений выбранного байта DAT | 65 536 |
| Наземная опора, флаги, знаковое состояние, порог, DAT[3F], слои | 9 072 |
| Коды занятости, маска владельцев, разности полей, состояния и направления | 93 312 |
| Области 1×1 / 2×2 / 3×2, края, восемь направлений, смешанные тайлы и объекты | 74 400 |
| **Всего** | **242 320** |

Сравниваются код и CF; оригинальная запись юнита должна остаться неизменной. Пространственные случаи включают снятие собственной области и порядок нескольких контактов. Сквозной тест берёт **настоящий DAT моста №7 ARMY__02**, делает обе стороны искусственной реки и проверяет:

- отказ на воде без опоры, проход с мостом, порог состояния и DAT[3F], ограничение слоем 1;
- отказ крупному юниту, часть области которого находится над неподдержанной водой;
- групповой переход рабочего с увеличенной областью 2×2 и обычного рабочего через мост 2×2;
- непересечение целей, резерв угловой клетки до переноса занятости и отсутствие оставленных ссылок после прибытия.

Это контролируемый сценарий модели, не утверждение о наличии такого моста или крупного рабочего на первой исходной карте. Обычная схватка, победа, хозяйственный цикл и сцены проверяются отдельно. Проверки используют подготовленные JSON из Git:

```sh
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-movement-admission
godot --headless --path . tests/TestRunner.tscn -- simulation
```

Повторное исследование требует установленной оригинальной игры и Unicorn:

```sh
python tools/verify_movement_admission.py --game /путь/к/игре --fixture /tmp/movement-admission.json
```
