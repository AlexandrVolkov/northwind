# Инструкция для Codex

Ты — помощник в переносе «Орды: Северный ветер» на Godot 4.7.2 .NET / C#. Ведущий разработчик — Claude: он решает, что попадает в `main`, ставит задачи и принимает работу. Ты работаешь, пока у Claude перерыв из-за лимитов. Общие правила проекта — в [AGENTS.md](../AGENTS.md): они обязательны и для тебя.

## Ветка

- Работай **только в ветке `codex-work`**. Не сливай её в `main`, не открывай PR в `main`, не пушь в другие ветки, не переписывай историю (`--force` запрещён).
- В начале каждого сеанса подтяни свежий `main`: `git fetch origin && git checkout codex-work && git merge origin/main`. Если слияние конфликтует, конфликт в твоих файлах решай сам; в чужих — бери версию `main` и запиши это в журнал.
- Делай **небольшие коммиты, один коммит — одна задача или законченная её часть**. В сообщении коммита первая строка — номер задачи и суть: `C3: decode WORK.FX sound bank`. Так Claude сможет перенести в `main` только нужное (cherry-pick).

## Что делать

1. Открой [codex-tasks.md](codex-tasks.md). Бери **первую задачу со статусом «открыта»** сверху вниз и поменяй статус на «в работе (Codex)».
2. Не трогай файлы из раздела «Заняты Claude» в том же файле. Если задаче они нужны, отложи её с пометкой в журнале и возьми следующую.
3. Закончив задачу, поставь статус «готово, ждёт проверки» и допиши запись в [codex-log.md](codex-log.md) (шаблон ниже).
4. Если задач не осталось — не придумывай крупных изменений сам. Можно: дописывать документацию по уже разобранному, добавлять тесты к существующему коду, разбирать форматы и адреса из раздела «Идеи» в codex-tasks.md. Новую задачу добавляй в конец очереди со статусом «предложена Codex».

## Как делать

- **Честность важнее объёма.** Восстановленное из кода или данных оригинала и придуманное — разные вещи. Всё, что не подтверждено (снимком, исполнением кода под Unicorn, байтами файла), помечай в docs как допущение. Не выдавай временные правила за оригинальные.
- **Доказательства — в docs/.** Адреса LE:1/LE:3, смещения полей, форматы, способ проверки. Неизвестные поля сохраняй, не выбрасывай.
- **Проверка логики оригинала** — как в `tools/verify_*.py`: исполнить код оригинала под Unicorn на сгенерированных случаях, сохранить в `tests/fixtures/` только параметры и SHA-256, повторить их в C#-тесте. Остатки регистров не сравнивать, а описывать.
- **Проверка графики** — сравнением со снимками оригинала (`docs/reference/`, `tools/dosbox_control.sh`, запуск — `docs/original-launch.md`).
- Код игры — C#, данные — JSON, конвертеры — Python. Не меняй `project.godot`, версию Godot/.NET, `AGENTS.md` и правила проекта; не удаляй и не ослабляй существующие тесты. Предложения по ним пиши в журнал.
- Перед коммитом прогони то, что доступно в твоём окружении:
  - `dotnet build`
  - `godot --headless --path . tests/TestRunner.tscn -- simulation` (и `scene`, `skirmish` при изменении сцен)
  - `python -m unittest discover -s tests -p 'test_*.py'`

  Если Godot, Unicorn или файлы игры недоступны, так и напиши в журнале: какие проверки не запускались. Не коммить заведомо падающее.
- В Git не добавляются ISO, EXE, установочные архивы, сырые DAT/WRK и их байтовые распечатки, локальные базы анализа (`build/`). Извлечённые PNG/JSON — можно, через конвертер в `tools/`.
- Вопросы к автору игры — в [questions.md](questions.md), раздел «Открытые». Вопросы к Claude — в журнал.

## Как Claude принимает работу

В начале каждого цикла Claude смотрит `git log main..origin/codex-work` и журнал. По каждой задаче он решает: перенести целиком, частично (cherry-pick, правки) или отклонить. Решение и причину он записывает в codex-tasks.md («принято в main #PR», «принято частично…», «отклонено: …») и в описание PR. Отклонённое не нужно переделывать, пока Claude не поставит задачу заново.
