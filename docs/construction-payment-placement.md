# Начальная оплата и геометрия строительства по EXE

Реализация: [OriginalConstructionRules.cs](../scripts/OriginalConstructionRules.cs). Этап продолжает [цепочку команд и создания объекта](building-command-lifecycle.md). Используется известная версия EXE с проверкой SHA-256; ожидаемые результаты получены исполнением исходных инструкций, без Python-реализации игровых правил.

## Начальная оплата: B083..B0E8

Участок получает шаблон из глобального указателя 0x500 и запись владельца из 0x508. Четыре u32 стоимости лежат в DAT по **+0x7c/+0x80/+0x84/+0x88**; запасы владельца — по **+0x18/+0x1c/+0x20/+0x24**.

Сначала последовательно проверяются все четыре запаса сравнениями **без знака**. Нехватка любого вызывает переход на 0xb1e4 без частичного списания. При достаточных запасах вычитаются все четыре значения. Назначение слотов ещё не связано с названиями ресурсов: четвертое поле пока не объявляется населением или иным конкретным ресурсом.

Параметры ARMY__02.DAT:

| Шаблон | Стоимость по четырём исходным слотам |
| --- | --- |
| Замок, индекс 2 | (0,0,0,0) |
| Казарма, индекс 3 | (50,80,150,2) |
| Лесопилка, индекс 4 | (30,50,80,2) |
| Забор, индекс 5 | (5,30,50,0) |

Нулевая стоимость в таблице сама по себе не подтверждает возможность строить объект через интерфейс. Полный набор разрешённых построек определяется отдельно.

TryDebitUpfront воспроизводит именно этот блок. Это **не вся транзакция строительства**: в исходнике списание находится перед вызовом проверки места по 0xb102. Ветка 0xb1e4 лишь очищает младшие биты действия и восстанавливает стек, без возврата запасов в этом участке. Нельзя автоматически переставлять эти операции или обещать откат при последующем отказе. При этом перед запуском строительного обработчика существуют проверки предварительного просмотра, поэтому из одного порядка инструкций не выводится пользовательский сценарий потери ресурсов.

## Проверка места: AD5F..AE39

Вход: шаблон, исходные координаты центра, данные карты и занятости. Настоящий вызов 0x68a0 выбирает шаблон; в тестовом исполнении этот вызов не заменяется.

Размер области берётся из **DAT[3]/DAT[4]**, в тайлах. Для замка он равен **4×3**; размер изображения 128×127 задаётся другими полями. Сдвиг координат на 5 означает шаг **32 единицы**:

```text
left = u8((raw_x >> 5) - floor(footprint_width / 2))
top  = u8((raw_y >> 5) - floor(footprint_height / 2))
```

Вычитание происходит в младших байтах регистров. Перенос сохраняет это переполнение, включая необычные исходные координаты, которые обычный интерфейс может отсеять раньше. Профиль поддерживает ненулевые размеры карты до 255 и область не больше карты; обработка повреждённых структур и других размеров не объявляется совместимой.

После проверки границы область обходится **по строкам, слева направо**. Для каждой клетки:

1. Проверяются три последовательные плоскости занятости, начиная с указателя 0x18ce и с шагом `width×height×4` байт. Первый ненулевой u32 немедленно возвращается как блокирующая относительная ссылка на объект. Назначение этих плоскостей пока не названо.
2. Если занятости нет, из значения MAP используется младший u16 индекса тайла.
3. Читается первый байт его 8-байтовой записи свойств, берутся младшие три бита. По этому классу выбирается **DAT[0x58+class]**. Ноль запрещает размещение, любое ненулевое значение разрешает клетку; в исходных шаблонах встречается 10, поэтому сравнение только с 1 неверно.

Если все клетки прошли проверку, возвращается свободное место. Блокирующий объект, запрещённая местность и граница различаются: у оригинала это комбинации ZF/CF; C# возвращает Clear, Occupied с исходной относительной ссылкой или Rejected. Occupied ещё не означает окончательный запрет для любого типа: в строительном обработчике 0xb10d–0xb14f есть отдельная ветвь проверки уже существующего объекта; она пока не перенесена. Порядок обхода важен: более ранняя запрещённая клетка может завершить проверку раньше более позднего занятого места. Внутри одной клетки занятость проверяется раньше класса тайла.

## Привязка к SEG

Это не классификация по цвету миникарты. Загрузчик по 0x38b1–0x38c5 читает n байт индексов миникарты, затем устанавливает указатель **0x18fe** на начало свойств и читает **8n байт**. Именно к этой таблице обращается проверка по 0xae02. В SEG2 это диапазон **[21+n,21+9n)**, ранее сохранённый как segment_properties_hex.

Установлен смысл младших трёх битов первого байта для данной проверки, но не названия восьми классов и не смысл остальных битов/семи байтов. На основании этого не объявляется восстановленной проходимость движущихся юнитов.

Функция предварительного просмотра 0xaf07 выполняет дополнительные вызовы и проверки, включая WRK с AH=4. ProbePlacement пока не заменяет весь механизм разрешения строительства, выбор владельца, специальные ограничения или создание объекта.

## Данные и воспроизведение

Импортёр **9** сохраняет в каждом шаблоне поле construction с footprint_width, footprint_height, terrain_mask и upfront_costs. `templates.json` теперь версии **4**. Исходные неизвестные записи и свойства SEG сохраняются полностью. Нужен повторный импорт.

[verify_construction.py](../tools/verify_construction.py) исполняет блок начальной оплаты до границы успеха 0xb0e9 или до начала отказа 0xb1e4; последующая очистка действия не входит в сравниваемый результат. Проверка места исполняется полностью до ret, включая исходный поиск шаблона. Никакие вызовы не подменяются.

[Синтетическая фикстура](../tests/fixtures/construction.json) содержит:

- **32 805** оплат: четыре исходные стоимости и синтетическая граница u32, девять значений для каждого запаса;
- **26 010** проверок места: пять размеров области, три маски, шесть вариантов занятости, обычные, граничные и переполненные координаты;
- исходные хэши, входы и SHA-256 всех последовательных результатов. В Git нет байтов EXE или оригинальных карт.

C# совпал с исходными инструкциями на всех **58 815** комбинациях. Проверка сцены дополнительно читает параметры казармы из DAT, списывает точную стоимость и проверяет известную область замка по настоящим MAP/SEG на **контролируемой пустой** карте занятости, затем с добавленной блокирующей ссылкой. Это не утверждение, что живая занятость оригинального мира уже восстановлена.

```bash
python -m pip install -r tools/requirements.txt -r tools/requirements-research.txt
python tools/verify_construction.py --game "/путь/к/игре" --output build/construction.json
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-buildings
```

Далее нужны назначение ресурсных слотов, построение живой карты занятости из объектов, дополнительные проверки предварительного просмотра и связанный цикл оплаты, размещения, создания и обновления здания.
