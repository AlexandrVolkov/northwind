# Кнопки приказов: DAT → режим интерфейса → состояние WRK (C7)

Карта из кода оригинала: [граф маршрутов](order-buttons-call-graph.md).
Полная таблица всех 28 шаблонов ARMY__02, шести слотов, подписей/клавиш,
WRK-диспетчеров и адресов состояний — `data/original_order_buttons.json`.
Её собирает `tools/order_buttons_source.py`, без выгрузки исходного кода.

## Исправление предпосылки C7

В старой формулировке задачи смешаны значки и обработчики. Уже проверенный
разбор [жизненного цикла](building-command-lifecycle.md) и
[интерфейса](interface.md) устанавливает правильную структуру:

| Поле от начала **настоящего DAT-шаблона** | Содержание |
|---|---|
| +0B, шесть по 8 байт | описания команд |
| команда +0, u16 | номер значка ARMY.SPR (1..4, 872..875 и т. д.) |
| команда +2, u32 | относительный указатель на подсказку **в DAT**, не на WRK |
| команда +6, u8 | режим интерфейса |
| команда +7, u8 | группа совместимости при групповом выделении |
| шаблон +3B, u32 | общий обработчик событий шаблона **в WRK** |

Подсказка начинается с u16 DOS scan code, затем текст CP866/стили и FF.
Два первых байта команды — единое u16 значка, а не условие или клавиша.
Наличие описания не означает доступность кнопки: её показывают биты
OBE[0F] (`WorkFlags`). `6EC1` и `B72D` уже перенесены, заново не разбирались.
У Олега исходное `07`: из шести описаний предводителя доступны слоты 0..2.

## Первый этап: активированная кнопка

Общий обработчик `616F..6294` работает с runtime-виджетом; выбранная
команда — таблица `[1978 + 12*slot]`. По `619E..61AB` сравнивает горячую
клавишу с `[1C35]`. Вход **61C3** уже означает подтверждённое нажатие:

- widget[1A] = 1;
- глобальный `[19C0]` = `40h | (slot << 3)`;
- widget[1B] = DAT mode;
- затем выбирается ветвь по mode.

| Mode | LE:1 | Что подтверждено |
|---|---|---|
| 0 | 622F | немедленная постановка номера слота; одиночная запись 623D или группа B8A2 |
| 1 | 4D41 | `[2]=1`, выбор точки движения |
| 2 | 4E27 | `[2]=2`, `[12]=0`, выбор цели атаки |
| 3 | 4FCE | выбранный тип из OBE[22], DAT через 68A0, AE57, `[2]=3`; размещение постройки |
| 4 | 50E5 | `[2]=4`, выбор лесной цели |
| 5 | 51AC | событие WRK AH=6 через D182, тип из `EDX+7+4*(slot-4)`, 68A0/AE57, `[2]=5`; размещение ямы рабочего или постройки предводителя |
| 6 | 5297 | `[2]=6`, выбор цели захвата |
| 7 | 538D | `[2]=7`, `[12]=0`, создаёт группу LE:3 1D1 («Выбор» производства) |
| 8 | 53C4 | `[2]=8`, `[12]=0`, выбор шахты |
| 9 | 54B4 | WRK AH=6, экран/группа из WRK-описания лаборатории; `[2]=9`, `[12]=7` |
| 11 | 5593 | `[2]=11`, `[12]=11`, создаёт группу LE:3 466E; «Выбор» предводителя |

Другие mode, в том числе 10, доходят до RET `622E`. Режим 10 есть во
внутренней ветви `55573`, но DAT-роутер его напрямую не выбирает.
Описание ветви не означает, что её полный сценарий перенесён.

`OriginalOrderDispatchRules.Activate` переносит **только 61C3..622F** и
возвращает выбранный исходный адрес; он не выполняет интерфейсный сценарий
по этому адресу. Уже проверенный `OriginalBuildingLifecycle.QueueDirectCommand`
переиспользуется для кодирования слота. Занятые файлы HUD не меняются.

## Второй этап: очередь объекта и вызов WRK

Режим 0 ставит `(old OBE[14] & 7) | 40h | (slot << 3)`. Три младших
бита ещё обозначают **текущее** действие; слот команды — в битах 3..5,
40h просит завершить текущее. WRK события AH=1 затем вызывают:

- **FS:E1 → LE:1 8227** для юнитов;
- **FS:41 → LE:1 C88C** для зданий.

Оба забирают указатель возврата в inline-таблицу из шести относительных
u32, пропускают 24 байта в адресе возврата и вызывают
`tableBase + table[OBE[14]&7]`. Номер состояния не является номером картинки.
При ZF=1 действия 8227/C88C переводят queued slot в младшие биты; этот
момент объясняет задержку между нажатием и началом действия.
Здание дополнительно обслуживает доступность ремонта через OBE[0F] bit 1;
это не скрытые байты в описании кнопки DAT.

Ворота имеют собственный switch `WRK D9C..E7B`, без inline-таблицы:
состояния 2/3/4 — открыть/закрыть/автомат. Переход queued slot выполняет
`E63..E76`; при появлении задаётся OBE[14]=84h, после инициализации — 4.
`E22` выставляет WorkFlags=18h, `E34` (если они ненулевые) — 14h.

## Значки из задания и реальные адреса

Адреса WRK ниже — ARMY__02.WRK. Адрес LE:1 после стрелки — переход по FS
из указанного WRK-обработчика, а не значение внутри DAT-кнопки.

| Значок / шаблон | Назначение | Mode / группа | WRK-состояние или UI |
|---|---|---|---|
| 1, ополченец | Стоять | 0 / 1 | слот 0: 6D → 82C3 |
| 2, ополченец | Идти | 1 / 2 | после выбора цели слот 1: 67 → 8273 |
| 3, ополченец | Атаковать | 2 / 3 | слот 2: 73 → 839F |
| 4, ополченец | Захватить | 6 / 6 | слот 3: 79 → 843E |
| 872, замок | Отмена | 0 / 0 | слот 0: 1F5; поддерживает состояние панели/прерывание |
| 873, замок | Ремонт | 0 / 0 | слот 1: 1BB → C80D, уже перенесённый ремонт |
| 874, замок | Выбор | 7 / 0 | интерфейс 538D; слот 2 таблицы 1B8 — пустой возврат |
| 875, замок | Построить (место) | 3 / 0 | слот 3: режим 4FCE, использует выбранный OBE[22] |
| 875, замок | Построить (прямое) | 0 / 0 | слот 4: 251; EDX=−59 → FS:49 (производство) |
| 2865, замок | Разрушить | 0 / 0 | слот 5: 25D → FS:12D → CCC4 |
| 1170, обычный рабочий №10 | Стоять | 0 / 1 | слот 0: 8B0 → 82C3 |
| 1171, рабочий №10 | Идти | 1 / 2 | слот 1: 8AA → 8273 |
| 1172, рабочий №10 | Рубить лес | 4 / 4 | слот 3: 8BC → 84AA |
| 1173, рабочий №10 | Вырыть яму | 5 / 0 | слот 5: 8C8 → 877F |
| 1455, рабочий №10 | Обслуживать шахту | 8 / 7 | слот 4: 8C2 → 86B6 |
| 1455, носильщик №8 | Отнести мешок | 0 / 5 | слот 4: A95 → 86B6 |
| **1172**, лесной носильщик №11 | **Отнести бревно** | **0 / 5** | слот 4: 9AC → 8659 |
| 1627, ворота | Открыть | 0 / 0 | слот 2: E22 → D5B1 |
| 1628, ворота | Закрыть | 0 / 0 | слот 3: E34 → D61D |
| 1625, ворота | Автомат | 0 / 0 | слот 4: E4C → D689 |

**1626 не упоминается ни в одном из шести слотов ARMY__02.DAT.** Его
назначение как картинки этим срезом не установлено. Не назначаем ему
вымышленную команду по соседству с тремя известными значками ворот.

Для предводителя №20: слоты имеют modes **0,1,2,0,5,11** и группы
**1,2,3,1,0,0**. Значок 875 в слоте 4 вызывает иной путь, чем замковый
значок 875: WRK AH=6 возвращает описание типа, после выбора места действие
предводителя 1197 вызывает FS:51 с EDX=6. Одного номера картинки
недостаточно для назначения поведения.

## Проверки и границы

`verify_order_dispatch.py` исполнил 61C3 для всех **6×256=1536** сочетаний
слота и mode. C# сверяет хеш всех 32 байтов виджета, queued command и
адреса ветви; неизвестные байты сохраняются. На этом проходе заглушек нет.

Дополнительно настоящие 8227/C88C либо switch ворот исполнены до входа
в обработчик каждого из шести состояний: **162 маршрута**, совпали с
данными конвертера. Сами обработчики тут не вызываются. Перед switch ворот
общий FS:8D/CA49 заглушён пропуском вызова; это явная граница проверки.
Python и C# проверяют, что опубликованные адреса совпадают с native-входами.

Полные сценарии выбора цели, строительства/лаборатории/захвата, изменения
условий WorkFlags, полный ход WRK и отрисовка UI не объявляются готовыми
этой задачей. Граф показывает их неперенесённые листья AE57, D182, DEE4,
DF2A, DF7E, E055, F781, 14E51; они не заглушены в активации — выполнение
останавливается **до** выбранной ветви. 6885/68A0/B8A2 уже перенесены.

Ограничение генератора графа: условные `je` в 61C3 исследуют тела известных
корней-назначений; после отсечения размера список «Вызывает» остаётся
совокупным и содержит их вызовы. Это не перечень прямых CALL из 61C3.
Скрипт ведущего не менялся.

```sh
python tools/order_buttons_source.py --game /path/to/Program_Executable_Files
python tools/verify_order_dispatch.py --game /path/to/Program_Executable_Files \
  --fixture /tmp/order-dispatch.json
godot --headless --path . tests/TestRunner.tscn -- order-dispatch
```
