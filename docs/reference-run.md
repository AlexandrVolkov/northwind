# Запуск оригинала как эталон поведения (25.11)

Оригинал `NORWIND.EXE` запускается без экрана: DOSBox-X под Xvfb, ввод через `xdotool`, снимки `import`, а память игры читается снаружи из `/proc/<pid>/mem`. Инструмент — `tools/reference_run.py` (команды `start`, `shot`, `click`, `key`, `peek`, `stop`). Исходные байты игры инструментом не сохраняются.

**Как находится сегмент данных.** Строка `D:\7bitlabs` лежит по `DS + 0x1EE4` (docs/original-launch.md). Эмулируемая RAM — анонимная область DOSBox-X в 64 МБ, линейный адрес эмуляции `L` находится по `начало_области + L`. Сегмент данных найден так: на экране кампании `peek 0x1ee4` даёт `D:\7bitlabs`, `peek 0x1c49` — ненулевой указатель. Значения `[6AA]`, `[6B6]`, `[6BA]` в меню кампании ещё нули: пул объектов создаётся при загрузке миссии.

**Проверено 25.11:** игра доходит до карты кампании (снимок в сессии), щелчок по карте запускает вступительный текст; всплывающее окно «Quit DOSBox-X» закрывается клавишей `n`.

**Зачем.** Единственный способ узнать истинное поведение там, где восстановленная логика неполна: дальние приказы движения, обход рек, ожидание контактов (`7FA7..8120`, `809D`), порядок объектов. Сверка по x86 проверяет функции по одной; эталонный запуск проверяет сценарий целиком (приказ → траектория).

**Что дальше (срез):** автоматически пройти меню до первой миссии, прочитать пул (`DS:[6AA]`), цепочки участников (`DS:97A + F5·владелец`), записи юнитов (позиции `+4/+8`, состояние `+2D`, маршрут `+28`) и сравнить траектории юнитов оригинала с `Skirmish` для приказов на дальние клетки.

## Находка: дальние приказы без «временного подбора» (25.11)

Эксперимент: убрана ветка `SearchPath`, которая при неудаче местного поиска строила промежуточные цели через AStar (`GuidedRouteSearches`), оставлен только перенесённый поиск `73F5/7497` с повтором из новой позиции (как в `7FF0 → 73F5`). Герой на первой карте, приказ на 10 / 25 клеток / 60,60:

| Вариант | цель (27,31) | цель (42,51) | цель (60,60) |
| --- | --- | --- | --- |
| как сейчас (AStar-подбор) | (27,31) | (34,50) в пути | (12,88), 3 подбора |
| только перенесённый поиск | (27,31) | (34,50) в пути | (39,55), 0 подборов |

Группы `simulation`, `original-route-search`, `original-movement-admission` проходят, а `skirmish` и `skirmish-ai` ломаются (армии не доходят до боя). Изменение **не принято**: без эталона неизвестно, обходит ли оригинал реку теми же повторными поисками или иначе; AStar-подбор остаётся адаптером в списке долга. Решит эталонный запуск.

## Меню оригинала под автоматикой (25.11, найдено руками)

Путь от запуска: вступительный текст на карте (`Return` пропускает) → «столб с указателями» (щелчок по «Игра» ≈ (418,283)) → список из 9 слотов «Новая игра» (первый слот ≈ (300,303)) → поле «Введите имя».

- Щелчок `xdotool click` слишком короткий: нужны `mousedown`, пауза 0,3 с, `mouseup` (так делает `reference_run.py click`).
- Раскладка в DOSBox-X русская: клавиша `a` печатает `ф`, `h` — `р`, `e` — `у`, `b` — `и`, `y` — `н`. Заглавную букву даёт `shift+клавиша`.
- Имя проверяется: сообщение «Такого персонажа в игре нет, смотри от авторов» (в EXE рядом «Такой персонаж уже есть» и «Герой с таким именем погиб») значит, что допустимое имя берётся из списка (вероятно, защита: имя показывает экран «От авторов»). Имена `ф` и `руфин` отвергнуты; `Руфин` с заглавной после очистки поля вернул к списку слотов без загрузки миссии (пул `DS:[6AA]` остался нулём).
- Следующий шаг: узнать допустимые имена (экран «От авторов» — `FROM.SMK`, `FROM_AUT.PAL`; таблица имён в данных EXE) и довести автоматику до загрузки миссии; потом читать пул оригинала через `reference_run.py peek`.

**Допустимые имена (сообщил пользователь, 25.11): Игорь, Олег, Эйрик.** Раскладка DOSBox-X русская: «Игорь» набирается `shift+b` `y`... см. таблицу клавиш по ЙЦУКЕН (`b`=и, `u`=г, `j`=о, `h`=р, `m`=ь).

## Первый сценарий на эталоне: дальний приказ (25.11)

Миссия 1 загружается через `reference_run.py mission` (имя Олег, около двух минут; на старте несколько юнитов сами идут к местам, потом стоят). Выбор юнита — щелчок по нему (`click`), приказ — правая кнопка мыши (`xdotool mousedown 3 / mouseup 3` с паузами); экран→мир: `мир = экран + (238, 644)` при начальной прокрутке. Объекты читаются командой `objects`.

**Результат.** Ополченец из (688,944) получил приказ на клетку (37,35), 16 клеток по диагонали/прямой. Траектория оригинала (позиции раз в 2 с, курсор маршрута `+28` растёт 1…16, потом снова 1 — новая прокладка): (688,944) → (768,1024) → (836,1040) → (883,1040) → … → (1070,1040) → (1143,1079) → (1183,1119) → (1192,1144). То есть три диагонали на юго-восток, девять шагов на восток по ряду 32, затем три диагонали и шаг на восток.

`Skirmish` (тот же старт и цель) строит **другой маршрут** при той же длине 16: `3333322222112333` (пять диагоналей, пять шагов на восток, два на северо-восток, на восток, три диагонали), потому что обходит клетки (33,33), (34,33), (34,34), которые его `CanStand` считает занятыми. В оригинале на этом участке нет объектов (`objects` в окне пусто), а плоскость занятости 0 пуста. Классы местности оригинала по тем же клеткам (низшие 3 бита дескриптора) — в таблице ниже: клетки с классами 1, 4, 5, 7 лежат в тех местах, где `Skirmish` ставит препятствия, но не совпадают с ними один в один — значит, допуск шага (`CanStand` ← `OriginalMovementAdmission`) расходится с оригинальным по скорости шаблона `DAT[58+класс]` или по правилам границы.

```
ряд  x=20..41 (класс)       
 29  0000000000040000000010
 30  0000000000000000000111
 31  0000000000001000001011
 32  0000000002011000000011
 33  0000000000110100057111
 34  0000000000001100055511
 35  0000000500010505555010
```

**Следующий срез (по правилу выбора среза):** сверить допуск шага `Skirmish.CanStand` с оригиналом по каждой клетке окна — прочитать классы и скорости шаблона ополченца в памяти оригинала (`DAT` шаблона по `[1C49]`, скорости `+58..+5F`) и найти, какое правило даёт препятствия (33,33), (34,33), (34,34) и отсутствие препятствий на ряду 33 слева. После этого повторить приказ и сравнить маршруты.

## Находка: карта оригинала сдвинута на 4 ячейки относительно импортированной (25.11)

`reference_run.py` теперь находит начало эмулируемой RAM по адресу сегмента данных (`DS_LINEAR = 0x17F010`): начало анонимной области хоста не совпадает с линейным адресом 0 (в одном из запусков смещение было 0x802000). Сигнатура `D:\7bitlabs` может встретиться несколько раз; берётся копия с правдоподобным `[6AA]`/`[1C49]`.

Из памяти оригинала в миссии 1 считаны `[18DE]`, `[18EE]` (ячейки карты), `[18FE]` (дескрипторы сегментов) и сравнены с `assets/imported/map.json`:

- размер 128 × 128 совпадает;
- **идентификаторы тайлов совпадают при сдвиге на 4 ячейки**: `оригинал[i] == импорт[i − 4]` (15 696 из 15 872 ячеек при сравнении внутри строки); без сдвига совпадают 662 из 16 384;
- классы местности (младшие 3 бита дескриптора) без сдвига различаются в 7 024 ячейках из 16 384, со сдвигом −4 совпадают в 87 % ячеек (оставшиеся 13 % не объяснены; возможно, различаются дескрипторы тайлов, а не только их порядок).

Загрузчик карты (`LE 3820..38E7`) читает файл несколькими `INT 21h / AH=3Fh` подряд и после каждого чтения сдвигает указатель (`add edx, ecx`); значения `[18FE]`, `[18F2]`, `[18EE]` — концы предыдущих чтений. Импортёр читает ячейки с фиксированного смещения 25 (`tools/import_game.py:359`). Расхождение в 4 ячейки (16 байт) похоже на разницу между фактическим началом массива ячеек в оригинале и смещением 25 импортёра.

**Что проверить следующим срезом:** (1) разобрать `3820..38F5` и найти, откуда читаются ячейки и какое смещение даёт `[18EE]`; (2) сопоставить тайлы с изображением экрана оригинала (прокрутка и начало экрана для этого пока не определены точно, визуальное сравнение 25.11 было неубедительным); (3) если сдвиг подтверждён, поправить импортёр и заново сверить допуск шага и маршруты (траектория оригинала в разделе выше).

Маршрут `Skirmish` с картой, сдвинутой на 4 ячейки, тоже не совпадает с оригиналом (`33333223122222` против наблюдавшихся трёх диагоналей, девяти шагов на восток и диагонального конца), так что сдвиг не единственная причина расхождения.
