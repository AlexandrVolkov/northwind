# Запуск оригинала как эталон поведения (25.11)

Оригинал `NORWIND.EXE` запускается без экрана: DOSBox-X под Xvfb, ввод через `xdotool`, снимки `import`, а память игры читается снаружи из `/proc/<pid>/mem`. Инструмент — `tools/reference_run.py` (команды `start`, `shot`, `click`, `key`, `peek`, `stop`). Исходные байты игры инструментом не сохраняются.

**Как находится сегмент данных.** Строка `D:\7bitlabs` лежит по `DS + 0x1EE4` (docs/original-launch.md). Эмулируемая RAM — анонимная область DOSBox-X в 64 МБ, линейный адрес эмуляции `L` находится по `начало_области + L`. Сегмент данных найден так: на экране кампании `peek 0x1ee4` даёт `D:\7bitlabs`, `peek 0x1c49` — ненулевой указатель. Значения `[6AA]`, `[6B6]`, `[6BA]` в меню кампании ещё нули: пул объектов создаётся при загрузке миссии.

**Проверено 25.11:** игра доходит до карты кампании (снимок в сессии), щелчок по карте запускает вступительный текст; всплывающее окно «Quit DOSBox-X» закрывается клавишей `n`.

**Зачем.** Единственный способ узнать истинное поведение там, где восстановленная логика неполна: дальние приказы движения, обход рек, ожидание контактов (`7FA7..8120`, `809D`), порядок объектов. Сверка по x86 проверяет функции по одной; эталонный запуск проверяет сценарий целиком (приказ → траектория).

**Что дальше (срез):** автоматически пройти меню до первой миссии, прочитать пул (`DS:[6AA]`), цепочки участников (`DS:97A + F5·владелец`), записи юнитов (позиции `+4/+8`, состояние `+2D`, маршрут `+28`) и сравнить траектории юнитов оригинала с `Skirmish` для приказов на дальние клетки.

## Находка: дальние приказы без «временного подбора» (25.11)

Эксперимент: убрана ветка `SearchPath`, которая при неудаче местного поиска строила промежуточные цели через AStar (`GuidedRouteSearches`), оставлен только перенесённый поиск `73F5/7497` с повтором из новой позиции (как в `7FF0 → 73F5`). Герой на первой карте, приказ на 10 / 25 клеток / 60,60:

| Вариант | цель (27,31) | цель (42,51) | цель (60,60) |
| --- | --- | --- | --- |
| как сейчас (AStar-подбор) | (27,31) | (34,50) в пути | (12,88), 3 подбора |
| только перенесённый поиск | (27,31) | (34,50) в пути | (39,55), 0 подборов |

Группы `simulation`, `original-route-search`, `original-movement-admission` проходят, а `skirmish` и `skirmish-ai` ломаются (армии не доходят до боя). Изменение **не принято**: без эталона неизвестно, обходит ли оригинал реку теми же повторными поисками или иначе; AStar-подбор остаётся адаптером в списке долга. Решит эталонный запуск.

## Меню оригинала под автоматикой (25.11, найдено руками)

Путь от запуска: вступительный текст на карте (`Return` пропускает) → «столб с указателями» (щелчок по «Игра» ≈ (418,283)) → список из 9 слотов «Новая игра» (первый слот ≈ (300,303)) → поле «Введите имя».

- Щелчок `xdotool click` слишком короткий: нужны `mousedown`, пауза 0,3 с, `mouseup` (так делает `reference_run.py click`).
- Раскладка в DOSBox-X русская: клавиша `a` печатает `ф`, `h` — `р`, `e` — `у`, `b` — `и`, `y` — `н`. Заглавную букву даёт `shift+клавиша`.
- Имя проверяется: сообщение «Такого персонажа в игре нет, смотри от авторов» (в EXE рядом «Такой персонаж уже есть» и «Герой с таким именем погиб») значит, что допустимое имя берётся из списка (вероятно, защита: имя показывает экран «От авторов»). Имена `ф` и `руфин` отвергнуты; `Руфин` с заглавной после очистки поля вернул к списку слотов без загрузки миссии (пул `DS:[6AA]` остался нулём).
- Следующий шаг: узнать допустимые имена (экран «От авторов» — `FROM.SMK`, `FROM_AUT.PAL`; таблица имён в данных EXE) и довести автоматику до загрузки миссии; потом читать пул оригинала через `reference_run.py peek`.

**Допустимые имена (сообщил пользователь, 25.11): Игорь, Олег, Эйрик.** Раскладка DOSBox-X русская: «Игорь» набирается `shift+b` `y`... см. таблицу клавиш по ЙЦУКЕН (`b`=и, `u`=г, `j`=о, `h`=р, `m`=ь).
