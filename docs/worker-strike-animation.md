# Рабочий: кадры взмаха и момент удара

В схватке рабочий проигрывает исходные кадры рубки. Ожидание следующего взмаха связано с кадром удара, а получение груза ждёт завершения последней анимации. Прежний немедленный сброс таймера при запросе взмаха удалён. Общая частота симуляции остаётся экспериментальной: совпадение последовательности вызовов не доказывает исходное время в секундах.

## Цепочка оригинала

Адреса — смещения в кодовом объекте LE той же версии NORWIND.EXE, что в [исследовании лесозаготовки](native-forestry.md). Точки подключения подтверждаются не наблюдением экрана, а машинным кодом:

- Рабочий ARMY__02.DAT №10 имеет WRK entry **7F5**. Ветвь обновления **WRK 883** вызывает FS:DD → **EXE 90E9**, затем **WRK 889** вызывает FS:E1 → **EXE 8227**, диспетчер рабочих действий. Поэтому анимация обрабатывается перед логикой рубки.
- **9210..9274** читает текущий тип анимации из младшего полубайта OBE[2D], запрос — из старшего. Флаг 80 в OBE[17] останавливает обработку. В этом переносе поддержаны стационарные состояния 0 и 3 с запросом 0 или 3; движение, поворот и специальные состояния остаются в прежних ядрах/мостах.
- **9275..92EE** выполняет переход: если завершённый тип совпадает с запросом, оба сбрасываются в 0. Поэтому запрос 33 не означает бесконечную анимацию. При переходе очищается OBE[24]; возврат к покою задаёт `DAT.u16[48] + heading × DAT[4A]`.
- **93AD..9424**, ветвь цели-клетки: младший полубайт становится 3; OBE.u16[28]/[2A] получают центры клетки из OBE[22]/[23], OBE[27] получает слой 1. Первый кадр — `DAT.u16[48] + 8 × DAT[4A] + heading × DAT[4B]`; OBE[26] получает DAT[4C]. Цель-объект с OBE[22]=FF в этот модуль не включена.
- **9429..945B** уменьшает байтовый OBE[26]. Когда он становится 0, увеличивается байтовый OBE[24]. Новый период берётся из DAT[4C] до кадра DAT[4E], затем из DAT[4D]. При прогрессе >= DAT[4B] выполняется переход 9275, иначе u16 кадра увеличивается. Переполнение байтов и слова сохранено.
- **945E..948B** только на прогрессе DAT[4E] обнуляет OBE[2F] и готовит вызов эффекта **9727**: координаты начала учитывают знаковые байтовые смещения DAT[60..6F] по направлению; цель — OBE.u16[28]/[2A]; код эффекта — DAT[70], файл армии — OBE[0], слой — OBE[27]. Модуль возвращает эти исходные аргументы, не исполняя полный обработчик эффекта.
- **856C..8573** пропускает работу, пока текущая анимация равна 3. После её окончания **8585..85A9** продолжает счётчик рубки. Последний запрос взмаха ещё не даёт груз: нужно дождаться завершения этой анимации.

Для рабочего №10: база кадров **1174**, DAT[4A]=11, DAT[4B]=7, DAT[4C]=1, DAT[4D]=1, DAT[4E]=6. Блоки рубки занимают **1262..1317**, по семь кадров на восемь направлений. Импортёр кадров включает все **56** изображений в готовый атлас (всего 509 кадров), использует прежнюю проверенную палитру COLOR_02.TAB/COLOR1.PAL. Для игры не нужен повторный импорт или ISO.

## Что подключено к схватке

`OriginalWorkerAnimation` обрабатывает запрос/продолжение/завершение взмаха перед рабочим заданием. Во время состояния 3 счётчик рубки не продвигается. Таймер OBE[2F] сохраняется при запросе и обнуляется на кадре удара; инициализация работы также больше не сбрасывает его произвольно и возвращается до первого обновления счётчика ожидания. Рендер получает реальный номер кадра из записи рабочего. Временная линия эффекта появляется на исходной границе удара и использует исходные координаты запроса.

При приказе движения, остановки или новой рубки мост запрашивает покой через очистку старшего полубайта OBE[2D] (операция **8C98**). Текущий взмах заканчивается, а новый не запускается автоматически. Это согласовано с поведением анимационного ядра; полный исходный диспетчер пользовательских команд ещё не заявляется перенесённым. Пауза замораживает всю запись и симуляцию.

## Проверки по x86

`tools/verify_worker_animation.py` использует Unicorn и исполняет исходные инструкции от **9210** до возврата либо границы вызова **9727**. На этой границе сохраняются аргументы эффекта; сам эффект не заменяется моделью на Python. Чужой владелец в тесте исключает переход края карты при возврате в покой. До 9210 не исполняются общий upkeep, изменение состояния и случайные проверки из 90E9.

**215 040** независимых шагов покрывают состояния 00/30/33/03, все 256 значений таймера, семь значений прогресса, разные направления и флаг остановки. Пять конфигураций DAT включают нулевые задержки, граничные кадры, переполнение u16 базы и знаковые смещения точки эффекта. Сравниваются все 54 байта записи и полный исходящий запрос эффекта.

Отдельная последовательность на настоящем DAT рабочего выполняет анимацию, затем оригинальный блок **8560..85CC**, до границы вызова получения груза **85CC** (сам callback здесь не исполняется). Она занимает **321 вызов** и содержит **20 ударов** на шагах 15, 31, …, 319 (нумерация с нуля). C# совпадает по каждой записи каждого шага, моментам эффектов и окончанию груза. SHA-256 исходного DAT в эталоне проверяется по включённому в Git шаблону.

Сквозной `economy` проверяет кадры до удара/при ударе, отсутствие преждевременного эффекта и груза, паузу внутри взмаха, семь доставок, смену леса и остановку внутри следующей анимации. Графическая проверка сохраняет `build/worker-strike.png`; чистая копия проекта использует только файлы Git. Python проверяет наличие всех кадров, размеры и существующие эталоны цветов.

```sh
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-worker-animation
godot --headless --path . tests/TestRunner.tscn -- economy
python -m unittest discover -s tests -p 'test_*.py'
```

Для повторного исследования (не для запуска игры):

```sh
python tools/verify_worker_animation.py --game /путь/к/игре --fixture /tmp/worker-animation.json
python tools/prepare_skirmish_frames.py /путь/к/игре
```

## Осталось перенести

Это не полный автомат рабочего. Ещё не подключены общий префикс **90E9..9210** (состояние, upkeep и общая случайность), исходный планировщик, полная цепочка прямых команд/WRK, полный автомат подхода/взаимодействия с лесопилкой (выбор, точка приёма, запрос и древесные переходы уже [перенесены отдельно](worker-delivery.md)), движение с грузом во всех состояниях и оригинальные эффекты **9727** с их WRK-обработчиками. Переходы карт при покое сюда не входят. Цены и частота симуляции пока учебные; остальные ресурсы и фермы остаются отдельными этапами плана.
