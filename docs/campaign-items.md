# Предметы кампании первой карты (ARMY__03, ARMY__00) — разбор, 22.11

Слоты 6 и 7 первой карты, кроме животных (см. [fauna.md](fauna.md)), держат объекты ARMY__03: **кувшины** (1, 30 «+золото», 33 «+фантом»), **сундуки** (9, 10, 11, 29), **ямы-ловушки** (12, 31), **камнепад** (2, 36), рукописи 1–3, «Руфин» (13) и ARMY__00 «Кувш. фантома» (29). В схватку они не загружены. Их поведение — записи ARMY__03.WRK (13 412 байт, сейчас не разобрано) и ARMY__00.WRK `0x4F3..`.

## Яма-ловушка (ARMY__03 №12, WRK `0x7F0`) — состояния, разобрано по дизассемблеру

Запись 43 байта; состояние в `+15`, кадр в `+1`, счётчик кадров `+2A`.

| AH | Что делает |
| --- | --- |
| 0 | `+22 = FFFFFFBFh`, кадр `+1 = 289h`, `+2A = 0` |
| 1, `+15 = 0` | раз в 20 обновлений (`[FS:10] & 1F = 0`) ищет объекты в квадрате 3×3 клетки вокруг ямы (службой FS:14B: угол = клетка − (1,1), размер 2,2); найдено что-то и `ebx = 0` → `+15 = 1` |
| `+15 = 1` | раз в 2 обновления кадр растёт до `+2A = 13h` (19 кадров открытия); службой FS:157 (`cl = FEh, ch = 2`, `+0D` на время вызова увеличен) проверяется область; когда кадры дошли до конца и служба вернула 0, `+15 = 2` |
| `+15 = 2` | раз в 256 обновлений → `+15 = 3` |
| `+15 = 3` | раз в 2 обновления кадр уменьшается до 0 (закрытие); в конце службой FS:157 (`eax = 0, ecx = 0, ebx = собственная ссылка`) яма снимает свой эффект, `+15 = 0` |

**Службы опознаны (22.11)** по таблице FS загрузчика (`analyze_executable.analyze`, `fs_assignments`): **FS:14B = LE:1 `11DDE`** — объекты в прямоугольнике: возвращает ближайшего враждебного (`edi`), число враждебных (`eax`: владелец объекта входит в маску `+22` ловушки) и число остальных (`ebx`); фильтры — не здание (`DAT[40] & 8020h`), видимость `+20`, состояние выше порога `DAT[46]`, слой `+0D & 3` разрешён `DAT[74]` ловушки; **FS:157 = LE:1 `D2D1`** — прямоугольник плоскости занятости: свободные клетки (или с `ebx`) занимаются ссылкой `eax`, а чужие объекты при `cl ≠ 0` убиваются (`+19 = 0`, `+17` = вид `ch`<<3), возвращается число найденных; **FS:111 = `BEBB`**; FS:1D = `81D9`.

**Перенесено:** `OriginalPit` (`scripts/OriginalPit.cs`) — автомат ямы целиком; сверка Unicorn с записанными службами (`tools/verify_pit.py`, `tests/fixtures/pit.json`, 1500 случаев, 47 открытий, 32 закрытия), C# совпал во всех. Службы 14B и 157 в проверке — записанные заглушки, их перенос и подключение к схватке — следующий срез.

**Что мешало перенести сразу (теперь снято для автомата):** службы FS:14B (поиск в квадрате) и FS:157 (область / снятие эффекта) в LE:1 не опознаны (таблица FS заполняется релокациями; в сыром образе указатели не читаются). Для переноса нужно: найти LE:1-подпрограммы этих служб (по таблице FS после релокаций или по вызовам из записей WRK с известным смыслом), сверить их через Unicorn, затем перенести состояния выше с фикстурой.

## Порядок следующих срезов

1. Таблица FS с релокациями → имена служб 14B, 157, 1D, 111 (`tools/`, запись в annotations).
2. Яма-ловушка и камнепад (одни службы области).
3. Кувшины и сундуки (подбор предметов, золото, фантомы): читать WRK `0xE4`, `0x71A`, `0x2B63`.
4. Рукописи и посохи ARMY__00 (WRK `0x86..`, `0x311`) — связаны с кампанией (Руфин, маги); исход зависит от сценарных переключателей (`Выключатель`, `Выход`).

## Ямы в схватке (22.11)

`SkirmishRules.Pits` (сцена включает): ямы-ловушки слота 6 (ARMY__03 №12 и 31, две на первой карте у клеток (126,39) и (126,43)) шагают перенесённым автоматом `OriginalPit` каждое обновление; кадры 289h..29Ch лежат на второй странице атласа и рисуются под юнитами. **Адаптеры:** службы 14B и 157 реализованы над актёрами схватки (`SkirmishPits.cs`), а не оригинальными `11DDE`/`D2D1`: поиск считает живых небоевые-не-здания юниты в квадрате 3×3 (враждебность по маске владельца `+22`), шаг области убивает юнитов в основании 2×2 и не занимает клетки занятости; слой и видимость не учитываются. Проверка: `PitChecks` (юнит в яме гибнет, автомат возвращается в состояние 0). Камнепад, кувшины, сундуки — следующие.

## Что выяснено по соседним службам (22.11, без переноса)

- **Камнепад (ARMY__03 №2/36, WRK `0x189`).** Каждые 4 обновления (`FS:10D & 3 = 0`) ищет объекты в квадрате 5×5 вокруг себя (`FS:14B`, `edx = 404h`, угол − 2); если есть, `FS:19` (LE:1 `9727`, создание эффекта) создаёт эффект ARMY__00 **типа 18h** (16×16, обработчик WRK `0x1012`) в случайной точке (±0x30 по x, +0x32 по y), раз в 32 обновления — звук 6. Эффект падает (`FS:A5`, `FS:A9`, 10 кадров, вторичный эффект `FS:AD`). Для переноса нужны `FS:A5`, `FS:A9`, `FS:AD` и обработчик типа 18h — цепочка из пяти служб.
- **`FS:157` (D2D1)** берёт размер основания из глобального `[273F]` (его оставляет последний вызов 68BD/68A0, в яме это кандидат из `11DDE`), поэтому точная сверка требует воспроизвести остаточное состояние поиска; адаптер ямы использует собственный размер 2×2.
- **`FS:129` = A444** — голос объекта: условие `(указатель записи − указатель DAT + [19EA]) & BL = 0` зависит от адресов в памяти оригинала, поэтому доли срабатывания не восстановить точно; адаптеры (звери, мельница, церковь, шахта) считают случайно. Мельница и церковь (WRK `0x131E`, `0x137A`) — только кадры здания (`FS:41`, перенесено) и этот голос.
- **Башня (WRK `0xCB9`)** ведёт себя не как стрелок: `FS:BD` (LE:1 `CB77`) — счётчик `+22` до 32h/3Ch, проверка посетителя по флагу `DAT[40] & 1000h`, учёт убийств в блоке участника (`+17B + 3·владелец`) и пометка цели (`+17 |= 20`): это переход «захват цели башней»; полный разбор — отдельный срез (башни ИИ строит, правил боя у них пока нет).

Порядок по значимости для игры: башня (CB77 и соседи), затем камнепад (цепочка A5/A9/AD), затем кувшины/сундуки.
