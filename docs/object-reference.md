# Первый объект и визуальный прогон движения

## Что подтверждено

В оригинальном сценарии за Олега левым кликом по экранной точке (350,424) выбран персонаж; панель оригинала показывает **«Ополченец»**. Ранее извлечённая таблица ARMY__02.DAT также содержит этот шаблон под индексом 0.

На снимке до выделения **кадр 71 ARMY__02.SPR**, размер 62×62, после перевода индексов через **COLOR_02.TAB** и шестибитную VGA DAC-палитру точно воспроизводит все **280 непрозрачных пикселей**. Единственное найденное положение кадра — экранный левый верхний угол **(321,393)**. Проверяется вся непрозрачная маска, а не её видимый фрагмент; UI-обрамление выделения не используется для совпадения.

Четыре участка ландшафта подтвердили неизменную камеру **(320,768)** и viewport **(336,216,448,448)**. Левый верхний угол спрайта в координатах карты получается **(305,945)**.

## Что остаётся гипотезой

В MAP_1_01.OBE запись по смещению 203 имеет имя шаблона «Ополченец» и пару (304,912). Разность с найденным углом спрайта равна **(+1,+33)**. Это перспективная привязка, но без чтения идентификатора объекта из состояния оригинала она остаётся **candidate_link_not_general_anchor**. Не распространяем её на все шаблоны, здания, направления и состояния анимации. Номер кадра означает, что этот кадр воспроизводит снимок; это не трассировка счётчика анимации в памяти.

## Перемещение

После выделения отправлен один правый клик в **(480,424)** экрана — **(464,976)** карты при подтверждённой камере. Сохранены шесть снимков на протяжении примерно трёх секунд после возврата отправки ввода. Команда завершения хода не посылалась.

В заранее выделенной области (336,400,204,40) измерен диагностический центр красных пикселей (`R>100`, `R>2G`, `R>2B`):

| Секунды после возврата отправки ввода | Центр X |
| --- | --- |
| 0.005 | 355.00 |
| 0.260 | 357.78 |
| 0.508 | 368.11 |
| 1.006 | 385.78 |
| 2.012 | 421.96 |
| 3.005 | 457.12 |

Камера однозначно совпала на всех шести кадрах, снимке до ввода и позднем снимке после остановки. Таким образом, наблюдается непрерывное экранное перемещение выбранного персонажа, а не прокрутка местности. Поздний снимок показывает персонажа возле указанной цели.

Цветовой центр — **не координата объекта и не якорь спрайта**. Анимация влияет на него; метод требует области без других красных объектов и не является универсальным трекером. Время хоста после возврата ввода — не внутренние тики игры. Из одного прогона не выводим скорость оригинала, формулу пути, сетку столкновений или готовую временную модель.

## Повторяемые инструменты

Проверка известного кадра по своему неизменённому снимку:

```bash
python tools/match_sprite_reference.py --game "/путь/к/игре" --screenshot before.png --spr ARMY__02.SPR --table COLOR_02.TAB --frame 71 --size 62 62 --viewport 336 216 448 448 --search 336 380 74 80
```

`--search` задаёт область поиска непрозрачного seed, viewport — область игрового поля. Отсечение хотя бы одного проверяемого непрозрачного пикселя не допускается. Без `--exclude` проверяется полная маска; явные исключения отдельно помечают частичное сравнение. Возвращаются unique/ambiguous/no_match, число проверенных/исключённых пикселей и хэш снимка. Другой кадр или направление могут не совпасть — это нормальный отрицательный результат.

Для серии PNG создайте capture.json вида `{"captures":[{"file":"after-0.png","seconds_after_input_return":0.005}, ...]}` с реальными монотонными временными отметками, затем:

```bash
python tools/measure_reference_motion.py --capture capture.json --roi 336 400 204 40
```

Метод требует того же масштаба снимка и выбранной вручную области, он не распознаёт персонажей самостоятельно. Все численные факты, входные хэши и исходные смещения сохранены в [object-reference.json](object-reference.json); оригинальные изображения в Git не включены.
