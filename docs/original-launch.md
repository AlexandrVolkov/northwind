# Запуск оригинала: причина запроса CD-ROM устранена

## Диагноз

Из InstallShield извлекается пустой файл `CD`. В этой версии игры он должен содержать **букву DOS-привода**, а не просто присутствовать рядом с EXE.

Проверка в NORWIND.EXE:

1. Открывает относительный файл `cd` через DOS `INT 21h / AH=3Dh`.
2. Читает **один байт** через `AH=3Fh`, `ECX=1` и закрывает файл.
3. Записывает прочитанный байт вместо `?` в строке `?:\7bitlabs`.
4. Пытается открыть этот путь; при неудаче возвращает ошибку 9.

Следовательно, при ISO на D: файл `CD` должен начинаться с ASCII `D` (`44` hex). Пустой файл не задаёт допустимую букву; отсутствие файла также не является рабочей настройкой.

Это не требует патча EXE, замены инструкций или отключения проверки. Используется предоставленный ISO с его исходным корневым маркером `7BITLABS.`.

## Повторяемая подготовка

Нужны DOSBox 0.74-3, распакованная папка игры с `NORWIND.EXE` и исходный ISO. Папку игры можно получить из `SETUP/DATA1.CAB` утилитой unshield или использовать уже установленную игру. Python-зависимостей, кроме стандартной библиотеки, для этого шага нет.

```bash
python tools/prepare_dosbox.py \
  --game "/путь/к/распакованной/игре" \
  --iso "/путь/к/Horde.ISO" \
  --output "/путь/к/новой/reference-run"

dosbox -conf "/путь/к/новой/reference-run/dosbox.conf"
```

Скрипт создаёт новую папку, копирует игровые файлы, сохраняет исходные байты `CD` в `original-CD.bin`, записывает один байт `D` в копию и подключает исходный ISO на D:. Опция `--drive E` меняет обе стороны согласованно. Существующая папка назначения не перезаписывается; исходная установка и ISO не изменяются. `launch-manifest.json` фиксирует хэши EXE/ISO и настройки CD.

Базовая конфигурация: 64 МБ, `svga_s3`, dynamic core, fixed 30000 cycles. Звук выключен (`-nosound -noearth`) для первичной проверки. Эта скорость эмулятора не считается подтверждённой скоростью оригинального геймплея.

## Ручная проверка в DOSBox

На отдельной копии игры, где ISO уже подключён как D:, из каталога с NORWIND.EXE:

```dos
echo D>CD
norwind.exe -nosound -noearth
```

DOS-команда echo добавляет перевод строки; это допустимо, поскольку программа читает только первый байт. Скрипт подготовки пишет ровно один байт.

Если ISO подключён на E:, запишите `E`, а не `D`. Подключение ISO само по себе не обновляет файл `CD`.

## Основания для вывода

Исходный NORWIND.EXE, 503 789 байт, SHA-256:

```
eb52f043143d763f5a595ae2175249976f278d1eebf0336ae032caf7bfa0c3a8
```

Статическое исследование этой конкретной версии:

- MZ-заголовок приложения: смещение 217 764; его `e_lfanew=10 648` указывает на LE по смещению 228 412.
- LE data-pages offset `0xFC00` относительно этого MZ даёт начало страниц 282 276.
- Первый кодовый объект: 36 страниц, размер `0x23DC2`. Объект данных начинается после них, по смещению 429 732.
- Строки `cd` и `?:\7bitlabs`: физические смещения 437 637 и 437 640; смещения внутри объекта данных `0x1EE1` и `0x1EE4`.
- Функция проверки начинается со смещения `0x4271` кодового объекта (физическое смещение 299 285). Дизассемблирование objdump в режиме i386 показывает обращения к этим строкам и указанную последовательность DOS-вызовов. Это разбор выбранного участка, а не полная загрузка и декомпиляция LE/WRK.

Ключевой участок, в смещениях внутри кодового объекта:

```text
4271: mov edx, 0x1ee1       ; "cd"
4276: mov ah, 0x3d
427a: int 0x21              ; open CD
4286: mov ecx, 1
428b: mov ah, 0x3f
428d: int 0x21              ; read one byte
4293: mov eax, [0x696]
4298: mov al, [eax]
429a: mov [0x1ee4], al      ; replace '?' in drive path
429f: mov edx, 0x1ee4
42a4: mov ah, 0x3d
42a8: int 0x21              ; open drive:\7bitlabs
42ac: jae success
42ae: mov eax, 9
```

## Что проверено, что осталось

С пустым `CD` воспроизводился запрос вставить диск. После записи `D` и подключения того же ISO на D: игра прошла к вступлению с картой и текстом; Escape перевёл в главное меню с пунктами «Игра», «Выход», «От авторов». EXE сравнен с исходным побайтово и по SHA-256, он не изменён.

Первый успешный запуск использовал `cycles=max`. Затем новая копия, созданная `prepare_dosbox.py`, отдельно проверена на fixed 30000: вступление и главное меню также открылись. Вход в меню снимает блокер CD-ROM. Полный эталон M0 ещё требует входа в игровой сценарий, сохранения и записи маршрута/боя. Звук, все миссии, сохранения и корректность временной модели этим запуском не проверены.
