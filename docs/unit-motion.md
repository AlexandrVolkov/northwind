# Автомат движения юнита (LE:1 `9210..95D3`)

Порт `OriginalUnitMotion` (`scripts/OriginalUnitMotion.cs`), сверка с x86 оригинала — `tools/verify_unit_motion.py`, 1500 случаев, `tests/fixtures/unit-motion.json`, повтор в `tests/OriginalUnitMotionChecks.cs`.

Состояние в младшей тетраде `+2D`, запрошенное — в старшей; `+17 & 0x80` пропускает обновление.

| № | Состояние | Что делает |
|---|-----------|-----------|
| 0 | покой | при смене запроса переключение 9275; иначе возврат |
| 1 | поворот | счётчик `+26`, шаг поворота 9653 (ZF — повернулся) |
| 2 | шаг | служба 70B0; BL бит 40h — конец |
| 3 | замах | кадр `DAT[4A]·8 + курс·DAT[4B] + база`; удар на кадре `DAT[4E]` — эффект через 9727 (точка `DAT[60+2·курс]`, код `DAT[70]`) |
| 4 | перемещение | служба 12930 |
| 5 | диапазон кадров | см. docs/rufin.md (`OriginalFrameRange`) |
| 6/7 | анимация отдыха / поворот в покое | кадр `((+31>>2)·DAT[78] + +27 + 8·(DAT[4A]+DAT[4B]) + 4·ΣDAT[4F] + 0x20)` |

Состояние 0 в 92CA для юнитов игрока на границе карты вызывает D12C/10799 (событие границы, гибель 95D3). Остаточные значения AL/BL на выходе воспроизведены как у оригинала.

Статус: модуль проверен, но ещё не подключён как драйвер юнитов схватки (там пока адаптеры); подключение — следующий срез.

## Шаг ходьбы (LE:1 `70B0..72FD`)

`OriginalUnitWalk` (`scripts/OriginalUnitWalk.cs`, `tools/verify_unit_walk.py`, `tests/fixtures/unit-walk.json`, 1500 случаев). Подсостояния в `+24 & 7`: 0 начало (обнуляет `+26/+27/+2C`, `+28 = FFFFFFFF`), 1 следующий шаг маршрута (7FA7: нет шага — конец, 1 — блок `BL|80h`, 2 — только поворот), 2 ожидание, 3 поворот и скорость, 4 движение.

Скорость = `DAT[58+тип] − (тип>>4)` (если бит 7 не стоит), `&3F`, плюс `+16>>5`; тип берётся из таблицы местности клетки (18EE → 18FE), при занятой клетке (бит 0 `+0D`) — тип 0. Каждый шаг делит скорость на счётчик `+2C` (по 16 единиц — шаг в клетке; на середине вызывается перенос занятости 9B0D), смещает юнита по вектору курса (19C7) и ведёт счётчик шага `+27` (пыль DAT[A2] через 9727 на последнем кадре шага). Конец шага — 813E (туман) и поиск врага D895. Кадр = `курс·DAT[4A] + (+27 & 0xF) + база`.

## Шаг перемещения (LE:1 `12930..12AE1`, состояние 4)

`OriginalUnitMove` (`scripts/OriginalUnitMove.cs`, `tools/verify_unit_move.py`, `tests/fixtures/unit-move.json`, 1500 случаев). Юнит каждое четвёртое обновление поворачивается на 1/32 круга к целевой клетке (угол даёт 6996), затем смещается на `скорость·(cos, sin)/16` по таблице DS:4790 (`Heading`) (скорость `+26`, перенос от умножения на 64 прибавляет 4). Если новая точка вне карты (18E6/18EA) или место занято (AC63), движение кончается (`BL|80h`); иначе перенос занятости (43B0) и обновление тумана (813E) каждое четвёртое обновление. Кадр — `курс>>2·DAT[4A] + +27` при курсе, кратном 4, иначе `курс + 8·(DAT[4A]+DAT[4B]) + 4·DAT[4F]`.

Таблица DS:4790 — не заполняемая при запуске, а статическая (32 шага `(x, y)` по квадратному кольцу со стороной 4, в объекте 3 образа); она встроена в `OriginalUnitMove.Heading`, проверка читает настоящую из EXE.

## Подключение к схватке (24.11)

Ходьба юнитов схватки теперь ведёт кадры по оригиналу: после каждого движения `MoveTick` вызывает `OriginalUnitWalk.Stride` (725C: счётчик шага `+27`) и `WriteFrame` (72D8: кадр = курс·DAT[4A] + кадр шага + база), а у остановившегося юнита ставится стоячий кадр курса (72CF + 92CA). Прежний адаптер отрисовки (смена кадра по времени, 8 в секунду) убран. Пыль из-под ног `DAT[A2]` пока не рисуется (в `Stride` передан пустой обработчик).

**Что ещё не подключено:** `OriginalUnitMotion` (автомат 9210), `OriginalUnitMove` (12930) и выбор шага `7FA7` — маршрут схватки по клеткам заменяет шаги маршрута оригинала (адаптер, `MoveTick` сразу входит в подсостояние 3 шага ходьбы). Перекрытия, которые нужно свести к одной реализации при подключении: `OriginalWorkerAnimation` (9210, состояния 0/1/3), `OriginalFrameRange` и `OriginalVanishAction.Motion` (состояние 5), `OriginalMotionPreparation.TurnAndAdvance` / `OriginalSpatialRules.AdvanceMotion` (7165..725C). Состояние 4 (12930) использует `+31` как номер из 32 направлений; проверка покрывает `+31 < 32`, а у магов `+31 = 7Fh` (инициализация) — прежде чем запускать состояние 4 вживую, выяснить по оригиналу, какие шаблоны его достигают.
