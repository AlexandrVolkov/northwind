# Корпус замка и статические наблюдения

## Проверка в оригинале

После первого прогона движения камера перенесена на север нажатием миникарты в экранной точке (828,254). Четыре участка ландшафта подтвердили камеру **(416,480)** при viewport **(336,216,448,448)**. Левый клик в (530,465) выбирает здание; панель показывает **«Замок»**. Сравнение спрайта выполнено по снимку до выделения, чтобы рамка интерфейса не мешала проверке.

Для кадра **884 ARMY__02.SPR**, размер **128×127**, таблицы **COLOR_02.TAB** и преобразования VGA DAC6 найдено единственное положение **(464,393)** экрана, или **(544,657)** карты. Совпадение частичное: из полной маски 10 800 непрозрачных пикселей явно исключён прямоугольник кадра **(16,0,10,40)** — 103 непрозрачных пикселя области флагштока. Все оставшиеся **10 697 пикселей** совпали точно.

Без исключения кадр 884 не совпадает: 24 пикселя отличаются в пределах области флагштока. Это согласуется с видимым анимированным флагом, но способ наложения и кадры анимации не установлены. Проверка полных кадров 876–892 с десятью таблицами цвета не дала полного совпадения. Нельзя обозначать результат как восстановление всего изображения замка.

Исходная запись замка в MAP_1_01.OBE по смещению 0 содержит пару (608,720). Разность с наблюдаемым левым верхним углом равна (-64,-63). Эта отдельная наблюдаемая связь не устанавливает общий якорь: у ранее найденного ополченца разность другая, а его движение до снимка не исключено.

Хэши ресурсов, снимков, координаты и размер маски: [castle-reference.json](castle-reference.json). Оригинальные изображения и ресурсы в Git не включены.

## Повторная проверка

Для неизменённого снимка той же сцены:

```bash
python tools/match_sprite_reference.py --game "/путь/к/игре" --screenshot north.png --spr ARMY__02.SPR --table COLOR_02.TAB --frame 884 --size 128 127 --viewport 336 216 448 448 --search 440 380 160 150 --exclude 16 0 10 40
```

Результат должен содержать `status: unique`, `comparison_scope: declared_exclusions`, 10 697 проверенных и 103 исключённых непрозрачных пикселя. Для другого положения окна замените экранные координаты. Неоднозначность или отсутствие совпадения не подтверждают привязку.

## Отображение в Godot

[render-observations.json](render-observations.json) фиксирует входные хэши, камеры, номера кадров, таблицы цветов и явные исключения. Импортёр версии 6 создаёт `observed_militia.png`, `observed_castle.png` и `observations.json`; окно **B** показывает их отдельно с ограничениями проверки. Фон собирается из MAP/SEG с тем же DAC6, спрайт — из SPR с PAL/TAB. Исключённая область остаётся фоном. На экране отсутствуют остальные объекты оригинального снимка, поскольку они ещё не подтверждены.

Несовпадение карты или хэшей делает `observations.json` недоступным с пустым списком образцов; старые PNG не предлагаются к просмотру. Этот режим не назначает якоря всем объектам OBE и не меняет демонстрационную симуляцию. Следующий шаг — восстановить флаг и проверить несколько направлений/состояний движущегося объекта, затем подтвердить связь исходных координат с рендерингом.
