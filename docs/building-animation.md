# Анимация и износ зданий (LE:1 C88C, хвост C8E0..CA49)

Перенесено `OriginalBuildingFrames` (`scripts/OriginalBuildingFrames.cs`), сверка — `tools/verify_building_frames.py`, `tests/fixtures/building-frames.json` (6000 случаев, исходный код под Unicorn, вызовы 9727 и 98CC — записанные заглушки).

Кадры шаблона: стадии `base .. base+DAT[4A]` следуют состоянию (`+19`; индекс — `DAT[4A]·(+19)/(DAT[45]+1)` с вычитанием из 4A), **анимация работы** — кадры `[base+4A, base+4A+4B)` (у лесопилки, шахты, казармы, лаборатории, завода и мельницы по 10 кадров). Целая постройка стоит на кадре `base+4A`, то есть в диапазоне анимации, и каждое второе обновление (младший бит глобального счётчика `[19EA]`) кадр сдвигается, по кругу. Повреждённая — кадр по состоянию (стадии разрушения). Состояние не выше `DAT[46]` («руина»): рабочие флаги `+0F`, команда `+14` и `+15` сбрасываются, и раз в 256 обновлений состояние падает на 1, пока не станет отрицательным; тогда здание рушится за несколько обновлений (обломки 9727, затем удаление 98CC). Так же постепенно разрушается пустая шахта: износ `B47F` (docs/ore-extraction.md) опускает её состояние, а кадры стадий показывают это.

В схватке (`Skirmish.TickBuildingFrames`) движок идёт для зданий 3, 4, 6, 9, 12, 15, 22, 23, 24 (их кадры есть в атласе: `tools/prepare_skirmish_frames.py` теперь добавляет и кадры анимации `[base+4A, base+4A+4B)`, и кадры рабочего №8 с рудой). Обломки не рисуются. Замок и линейные шаблоны (забор, мост) пока не включены: их кадры не в атласе.
