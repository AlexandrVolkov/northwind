# База ассемблера и учёт разбора

Для переноса создана воспроизводимая локальная база кода, данных, ссылок и статусов. Её источники — NORWIND.EXE, шесть DAT и шесть WRK с SHA-256 из [профиля](code-analysis.json). REA 6.9.0 с Ghidra 12.1.4 действительно выполнил анализ отдельных модулей; экспортированы инструкции **877 обнаруженных функций, 37 171 строка инструкций**. [Отчёт REA](rea-assembly-inventory.json) содержит версии, идентификаторы Evidence, хэши модулей и результаты семи экспортов.

Это база для дальнейшей работы, а не заявление о восстановлении всех функций или исходного авторского ассемблера. Преимущественный Assembler с C-обёрткой — сведения пользователя; язык исходного текста не устанавливается одним наличием x86-инструкций. При ручном ассемблере особенно важно сохранять соглашения регистров, флаги, общие хвосты и несколько входов в одну подпрограмму.

## Где смотреть

- [Реестр покрытия](assembly-progress.md): статусы участков, адреса, доказательства, реализации и ограничения.
- [Машинный отчёт](assembly-coverage.json): все девять модулей, их полные диапазоны, незакрытые области и проблемы декодирования.
- [Редактируемые пометки](../data/reverse_engineering/annotations.json): источник статусов, сохраняемый в Git.
- `build/assembly/assembly.sqlite`: полная локальная SQLite-база, включая исходные байты, инструкции, граф переходов и REA Evidence.
- `build/assembly/*.asm`: сплошной кандидатный листинг и листинг по обнаруженному потоку управления.
- `build/rea-assembly-initial/*.rea.asm`: объединённые инструкции, наблюдённые Ghidra через REA.
- `build/rea-assembly-initial/*.investigation.json`: сохранённые расследования REA; сессии закрыты, Evidence сохранён до очистки.

Содержимое `build/` не включается в Git. В репозитории остаются генераторы, хэши и пометки. Это позволяет сохранять прогресс между сессиями без добавления оригинального EXE или его байтов в историю проекта. Локальную базу и архив результатов можно хранить отдельно и открыть на Windows через SQLite Browser; для просмотра таблиц Ghidra не нужен. Windows-запуск исследовательского MCP-экспортера отдельно не проверен; текущая сборка анализа выполнена в Linux. Запуск самой игры не требует этих инструментов.

## Три независимых вида сведений

| Вид | Что означает | Чего не доказывает |
| --- | --- | --- |
| `linear-candidate` | Каждый байт модуля представлен кандидатом x86/32-инструкции или `.byte` | Что область действительно исполняется или правильно выровнена |
| `flow-candidate` | Декодирование от входов LE, указателей DAT/FS и размеченных адресов с переходами и остановками | Полноту достижимости, смысл кода и правильность всех границ функций |
| REA/Ghidra | Инструкции функций, определённых Ghidra при заданных корнях, с Evidence и профилем | Исходные имена автора, полное обнаружение функций или точную модель всей DOS-программы |

Все модули имеют собственные относительные адреса: `LE:1`, `LE:2`, `LE:3`, `ARMY__00.WRK` … `ARMY__05.WRK`. Размер и SHA-256 проверяются. Физические страницы EXE связаны с объектами через `source_ranges`; нулевой хвост LE учитывается отдельно от байтов файла. Родительский EXE целиком сохранён в локальной таблице `sources`; области вне отображённых страниц перечислены в отчёте как **неразобранные контейнерные/загрузочные области**. Они не теряются и не выдаются за уже изученный 16-битный код.

REA импортирует каждый кодовый модуль отдельно как raw x86/32 с отображением начала по 0. Это база координат файла, а не утверждение об истинной точке входа игры: вход LE добавляется отдельным seed. Полная релокация LE и сегментная модель DS/FS здесь не построены. В частности, абсолютный операнд DS нельзя автоматически считать ссылкой на код с тем же числом. Проверенные присваивания FS дают отдельные межмодульные рёбра; остальные косвенные переходы сохраняются неразрешёнными.

WRK содержит встроенные данные. Например, EXE+C88C сдвигает адрес возврата на 24 байта и выбирает относительный обработчик действия. Наш просмотр потока отдельно сохраняет шесть u32 такой таблицы и не декодирует их как обычное продолжение вызова. Другие таблицы и спорные перекрытия остаются явными пробелами. Ghidra может самостоятельно интерпретировать часть таких данных как код; его наблюдение сохраняется с исходными ограничениями и не повышает статус участка.

## Статусы

- `unreviewed` — участок ещё не описан. Он всё равно присутствует в учёте.
- `partial` — часть назначения/ветвей разобрана; ограничения обязательны.
- `verified` — поведение в указанной области подтверждено, перенос ещё не помечен завершённым.
- `ported` — указанная операция перенесена в C# и имеет ссылку на реализацию и доказательства. Действуют её перечисленные предусловия.

Статусы относятся к **полуоткрытым диапазонам `[start,end)`**, а не к автоматически найденному имени функции. Текущее число пометок и их статусы смотрите в [живом реестре](assembly-progress.md): он генерируется из `annotations.json`. Поиск пути в широком диапазоне остаётся `partial`, поскольку неперенесённые/недоказанные ветви нельзя скрыть общим названием модуля. Если пометки позже пересекутся, отчёт сохранит все утверждения и выберет более консервативный статус.

Сумма диапазонов равна полному размеру каждого модуля: между размеченными участками автоматически остаются `unreviewed`. Число инструкций, автоматических функций или байтов со статусом не является процентом готовности игры.

## Как продолжать разбор

1. Выбрать участок из `unreviewed`, либо конкретный незакрытый вызов нужной игровой системы. [Индекс WRK](logic-handlers.md) и [карта систем](game-logic-map.md) помогают найти вход.
2. Смотреть инструкции, вызывающие места, данные и таблицы. Давать смысловое имя как рабочую гипотезу, сохраняя исходные координаты.
3. Добавить пометку в `annotations.json`: уникальный `id`, модуль, `start/end`, имя, класс `code/data/unknown`, статус, пути доказательств и реализации, ограничения. Для статуса `ported` приложить реализацию и проверку; не закрашивать соседние ветви автоматически.
4. Синхронизировать пометки и отчёт командами ниже. Это не требует повторного чтения ISO/EXE или нового запуска Ghidra; инструкции и REA Evidence сохраняются. Инструмент проверяет диапазоны, уникальность ID, источники и ссылки. При изменении самого исходного профиля нужно строить новую базу в новой папке.
5. Сохранить изменения пометок и отчётов в Git. Отдельный реестр не зависит от текущей REA-сессии и не пропадает при её закрытии.

После изменения пометок:

```sh
python tools/assembly_database.py sync --db build/assembly/assembly.sqlite
python tools/assembly_database.py report
```

## Воспроизведение

Исследовательские зависимости отделены от Godot:

```sh
python -m pip install -r tools/requirements.txt -r tools/requirements-research.txt
python tools/assembly_database.py build --game /path/to/game \
  --output build/assembly --summary docs/assembly-coverage.json
python tools/assembly_database.py report
```

REA устанавливается отдельно (`rea-agents@6.9.0`), native-провайдеру нужны Ghidra и полный JDK 21+. В текущем окружении CLI был установлен локально; собственный MCP-клиент экспортера использует тот же REA, не требует появления новых tools в уже открытом клиенте Codex и не меняет его глобальные настройки.

```sh
# Перед этим задать JAVA_HOME и GHIDRA_INSTALL_DIR установленным движкам.
python tools/export_rea_assembly.py --db build/assembly/assembly.sqlite \
  --output build/rea-assembly --rea /absolute/path/to/rea
python tools/assembly_database.py import-rea --db build/assembly/assembly.sqlite \
  --evidence build/rea-assembly --report docs/rea-assembly-inventory.json
python tools/assembly_database.py query --db build/assembly/assembly.sqlite \
  --module LE:1 --address 0x73f5 --limit 20 --view rea
```

Каждый экспорт сохраняет полный JSONL результатов, seeds и bundle расследования. Ошибки провайдера и неизвестная схема ответа не превращаются в пустую «успешную» базу. Seeds являются кандидатами анализа, а не восстановленными символами автора. Импорт сверяет SHA-256 Evidence с модулем и сохраняет наблюдения в таблицах `rea_evidence`, `rea_functions`, `rea_instructions`.

Примеры SQL для просмотра без Python:

```sql
SELECT module, start, end FROM coverage WHERE status='unreviewed';
SELECT module, start, end, name, limitations FROM annotations WHERE status='partial';
SELECT * FROM edges WHERE kind='unresolved-indirect';
SELECT address, assembly FROM rea_instructions
WHERE module='LE:1' AND address BETWEEN 29685 AND 29716 ORDER BY address;
```

Дальше можно разбирать фермы, найм, бой и переходы мира целыми сценариями, отмечая использованные участки в общей базе. Реестр дополняет игровые проверки; сам по себе он не делает неперенесённую механику готовой.
