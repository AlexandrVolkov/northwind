# Лесозаготовка и изменение ландшафта из EXE

В схватке используется критерий леса, локальный поиск, счётчики рабочего и замена тайлов из NORWIND.EXE. Подготовленные данные включены в Git; для игры не нужны EXE, ISO или Python. Полный автомат рабочего и его анимация ещё не перенесены.

## Установлено по исполняемому коду

Адреса ниже — смещения в восстановленном кодовом объекте LE, версия EXE SHA-256 `eb52f043143d763f5a595ae2175249976f278d1eebf0336ae032caf7bfa0c3a8`.

- **D101..D12B:** низкое слово клетки MAP выбирает восьмибайтовый дескриптор SEG. Лес пригоден при `(descriptor & 0xF07) == 1`. Цвет миникарты в проверке не участвует.
- **C35F..C438:** поиск в прямоугольнике вокруг области объекта, по строкам сверху вниз, слева направо. Рабочая цепочка сначала ищет в радиусе 1, затем DAT[47]. Перенос поддерживает непустую область объекта внутри карты, байтовые размеры карты и размер поисковой области до 255 без переполнения её правого/нижнего конца. Исходное поведение при области объекта за картой не включено в контракт.
- **84F0..8535:** расстояние до клетки по максимуму модулей двух координат должно равняться байтовому `(ширина области << 4) + 16`; для рабочего — 32. Перед рубкой выполняется уже перенесённый поворот к цели.
- **8542..8552 → 84E1:** младшие пять бит OBE[34] получают DAT[78], OBE[15] увеличивается. Для рабочего DAT[78] = 20. Старшие биты OBE[34] сохраняются.
- **8585..85A9 → 8AF4 / 8C89:** порог ожидания равен `u8(DAT[75] - high8(DAT[75] * OBE[16]))`. Пока OBE[2F] меньше порога, он увеличивается; иначе ставится запрос взмаха, копируются координаты цели и уменьшается OBE[34]. У рабочего DAT[75] = 8.
- **85A9..85CC:** после завершения младшего счётчика к OBE[34] прибавляется 0x20. При результате >= 0xE0 счётчик обнуляется и вызывается CFAC с AX=0x201, CX=0x101. В нормальном цикле это попытка замены леса после седьмого груза. Счётчик принадлежит **рабочему**, сохраняется между доставками и сменой цели; это не запас древесины в клетке. Следующий callback 123D3 вызывает WRK с AH=7, AL=3; в схватке ему пока соответствует явная смена шаблона рабочего и груза.
- **85D5..85E1:** к OBE[16] прибавляется 5 как u8; если результат отрицателен как i8, записывается 127. Это не обычное беззнаковое насыщение; полное назначение байта не объявляется восстановленным.

## Замена тайлов

**CFAC / CF07 / CD72 / CE9D** выбирают вариант очищенной поверхности по четырём угловым кодам SEG, затем подбирают согласованные соседние тайлы в области 3×3. Варианты перечисляются по исходному индексу SEG. Выбор использует `(randomByte * count) >> 8`; при непустом списке расходуется один случайный байт. Первый пробный ключ CFAC сохраняет AH индекса кандидата перед сдвигом; эта особенность воспроизведена и проверена на каталоге с индексами выше 255.

Изменение атомарно: если соседу не найден совместимый вариант, **все записи MAP отменяются**, но расход случайных байтов сохраняется. На успехе меняется только младшее слово клетки; старшие 16 бит сохраняются. Пример первой карты: `(6,10)` успешно меняет лес на тайл 199; `(10,20)` при начальном индексе RNG 0 не меняется из-за отсутствия совместимого варианта. Поэтому нельзя обещать фиксированное число грузов до исчезновения любой клетки.

Таблица девяти масок находится в **объекте LE 3, +7C0**, таблица 256 случайных байтов — в **объекте 2, +297E**. Это подтверждается записями релокаций операндов **CDC2** и **9E4A**. `tools/forestry_source.py` проверяет SHA-256 EXE и обе точные записи перед извлечением в `data/original_terrain.json`. Исходный EXE в Git не добавляется.

Рендер использует изменённые клетки, миникарта обновляется из цветов SEG/PAL (`terrain_colors.json`, импортёр 11). Проверка строительства и маршрутов читает тот же MAP. После доставки рабочего с очищенного участка запускается исходный локальный поиск следующего леса; если подходящего участка нет, он останавливается с сообщением.

## Что ещё временное

Полный диспетчер рабочего, подход к лесу, поиск и дистанция сдачи груза, анимация и эффекты ещё требуют переноса. В оригинале OBE[2F] обнуляется обработчиком удара **945E**; пока мост схватки обнуляет его сразу при постановке взмаха. Из-за этого и экспериментальных 30 обновлений/с временной ритм рубки ещё не точен. Не следует трактовать совпадение счётчиков как совпадение времени.

Перенос ландшафта использует отдельный воспроизводимый поток таблицы RNG, начиная с индекса 0. В полной игре поток общий; его расписание с боем и другими действиями ещё не подключено. Маршрут остаётся Godot AStarGrid2D, цены и ограничения схватки — учебными.

## Проверки

`tools/verify_forestry.py` исполняет оригинальные инструкции под Unicorn и ограничивает допустимые участки управления. Эталон содержит параметры и хэши результатов, а не модель ожидаемых правил на Python. C# сверяет полные записи рабочего, MAP и индекс RNG:

| Область | Случаев |
| --- | ---: |
| Критерий SEG, все младшие u16 и три старших слова | 196 608 |
| Поиск, края допустимой области, разные размеры и радиусы | 846 |
| Инициализация работы, байтовые переполнения | 4 608 |
| Ожидание и запрос взмаха | 48 608 |
| Изменение OBE[16], все байты | 256 |
| Замена поверхности на трёх синтетических каталогах | 768 |
| Завершение груза вместе с вызовом изменения карты | 96 |
| Настоящая первая карта, границы и ошибки подбора | 76 |
| **Всего** | **251 866** |

Дополнительно проверяются переход реальной клетки из запрета в разрешение строительства, атомарный отказ с расходом RNG и пользовательский цикл семи доставок с переходом к следующему участку. Графический режим сохраняет снимок после изменения ландшафта. Проверки запускаются на включённых в репозиторий данных:

```sh
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-forestry
godot --headless --path . tests/TestRunner.tscn -- economy
```

Воспроизведение исследования требует оригинальной установленной игры и `tools/requirements-research.txt`:

```sh
python tools/prepare_forestry.py /путь/к/игре
python tools/verify_forestry.py --game /путь/к/игре --fixture /tmp/forestry.json
```
