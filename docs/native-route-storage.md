# Хранение маршрутов оригинала

Перенесены упаковка результата поиска, чтение направления и освобождение блока. Это часть движения, **не исходный алгоритм поиска обхода**. В схватке путь по-прежнему строит Godot AStarGrid2D с четырьмя соседями; затем он хранится в `OriginalRoutePool`, а движение получает шаги через `SkirmishRoute`. Оригинальные EXE и эмулятор нужны только для повторного исследования, не для запуска проекта.

## Основание в коде

Источник: `NORWIND.EXE`, SHA-256 `eb52f043143d763f5a595ae2175249976f278d1eebf0336ae032caf7bfa0c3a8`. Адреса — смещения восстановленного LE-кода.

| Участок | Подтверждённое поведение |
| --- | --- |
| `2480–24A0` | Для каждого владельца помечает первые байты 128 блоков значением `FF`; хвосты блоков не очищает |
| `802C–8074` | В арене владельца `record[03] * 2000h` ищет первый свободный блок с шагом `40h`; записывает удвоенное смещение в `record[28..2B]` |
| `8074–809B` | Читает результат планировщика как байты направлений; кладёт два полубайта в байт, младший первым; бит `8` завершает путь |
| `809D–80A4` | Если блоков нет, возвращает текущее направление и статус `AH=2` для повторной попытки |
| `7FA7–7FC6` | `record[28]` — курсор полубайта, `FFFFFFFF` означает отсутствие пути; чётный курсор читает младший полубайт |
| `7FCC–7FF0` | При терминаторе освобождает блок и сравнивает текущую клетку с целью; нужен новый поиск, если цель ещё не достигнута |
| `811A` | Увеличивает курсор после успешного допуска и резервирования очередного шага |
| `8120–813D` | Освобождает блок по `(cursor >> 1) & ~63`, меняя только его первый байт на `FF`, и сбрасывает курсор |

Направления 0–7: север, северо-восток, восток, юго-восток, юг, юго-запад, запад, северо-запад. Формат поддерживает все восемь; выбор диагоналей в схватке пока не включён.

### Граница длинного пути

После записи байтов 0–62, если терминатора ещё нет, `8095` выставляет старший бит байта 63, **сохраняя его младший полубайт**. Исходный упаковщик не копирует туда следующую пару направлений. Это воспроизводится в ядре и отдельно покрывается вариантами старого содержимого блока. Нельзя считать блок обычным массивом 127 новых шагов.

Адаптер схватки подаёт максимум **125 шагов и терминатор**: последний терминатор помещается в старшую половину байта 62. Остаток длинного приказа не теряется: цель остаётся в `Goal` либо в боевой цели, и после завершения префикса существующий диспетчер строит продолжение. Полный исходный контракт планировщика на этой границе ещё предстоит восстановить.

## Подключение к схватке

- Общий пул для отрядов и нанятых рабочих; свободный блок ищется отдельно у каждого исходного владельца.
- В записи отряда хранится настоящий курсор `+28`, вместо очереди координат. Координаты для отображения маршрута восстанавливаются из направлений.
- Поворот, проверка проходимости, резервы и движение используют прежние перенесённые ядра. Курсор сдвигается после допуска следующего шага.
- Остановка, смена приказа, препятствие и уничтожение освобождают маршрут. Адаптер также освобождает блок сразу после выдачи последнего шага, раньше следующего вызова исходного обработчика терминатора.
- `+28` — поле с несколькими назначениями: анимация рубки использует `+28/+2A` для двух координат дерева (`OriginalWorkerAnimation`, исходный обработчик WRK). Адаптер освобождает только выданный ему живой маршрут; пустой маршрут не интерпретирует координаты дерева как курсор. Переход проверен отдельно и полным хозяйственным сценарием.
- При заполнении всех 128 блоков владельца новый путь не перезаписывает чужой. Прототип возвращает неуспех планирования, а его существующий диспетчер может повторить поиск; это не полный автомат оригинального `AH=2`.

## Проверка

`tools/verify_route_pool.py` исполняет настоящие инструкции x86 в Unicorn. Перехват останавливает исполнение на границах поиска и допуска движения; неожиданные переходы и исчерпание лимита инструкций считаются ошибкой. Логика упаковки, чтения и освобождения в Python не подменяется вычисленной моделью. В Git сохраняются параметры и SHA-256 результатов, без байтов EXE.

| Набор | Число сравнений | Покрытие |
| --- | ---: | --- |
| Упаковка и выделение | 480 | Владельцы 0/1/3/31, 0/1/127/128 занятых блоков, длины 0–255 с границами 124–128, три варианта старых хвостов |
| Чтение и освобождение терминатора | 16 384 | Все 256 значений байта, обе половины, байты 0/1/62/63, совпавшая и несовпавшая цель |
| Освобождение | 65 540 | Все 16 384 курсора каждого из четырёх владельцев и отсутствие пути |
| **Всего** | **82 404** | C# сравнивает хэши полного блока/арены и курсора |

Дополнительно проверены совместное использование, изоляция владельцев, просмотр пути, сдвиг курсора, отмена, повторное выделение, заполнение арены и освобождение внутреннего блока. Связанный сценарий отдаёт обычный приказ на 140 шагов, проходит границу 125 шагов и проверяет конечную позицию и отсутствие старой занятости.

```sh
PYTHONPATH=/path/to/unicorn python tools/verify_route_pool.py \
  --game /path/to/game --fixture tests/fixtures/route-pool.json
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-route-pool
```

Нужны Godot 4.7.2 .NET и SDK 10. Параметр `PYTHONPATH` нужен только если Unicorn установлен в отдельную папку; штатные проверки C# обходятся без него и без оригинальных файлов.

## Далее

`73F5` готовит размер объекта, слой, маску владельца и локальные границы поиска ±16 клеток. `7497–79BF` содержит обход препятствий, ветвление и восстановление пути. `7FA7–811F` связывает поиск с допуском шага, ожиданием и воздействием на другие объекты; в `9C23` найден бюджет пяти поисков. Эти части ещё не перенесены. Необходимы отдельные сравнения маршрутов, порядка обхода и переходов на динамической занятости, прежде чем заменять AStar или объявлять движение полностью оригинальным.
