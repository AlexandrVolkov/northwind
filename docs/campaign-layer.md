# Слой кампании: регионы (LE:1 `10BD4..10E19`, `110C8..11150`)

Таблица регионов по адресу DS:`3E87` (число регионов — `[6C9]`, армий — `[6C6]`): `841h` байт на регион — байт 0 (бит 0: регион существует) и по `84h` байт на запись армии. Поля записи (по использованию, имена описательные): `+0` номер армии, `+1..10` отношения к армиям (2 — враг, 3/4 — союзник), `+11` сила, `+17` население (больше `7CFh` — армия присутствует), `+57` бит 0 — состояние войны, `+58` бит 0 — рост, `+59` — осела, `+20/+21` клетка военачальника.

`OriginalCampaignRegions` (`scripts/OriginalCampaignRegions.cs`, `tools/verify_campaign_regions.py`, `tests/fixtures/campaign-regions.json`, 300 случаев):
- `Tick` (10BD4): каждое 1024-е обновление население армий с флагом роста растёт на 10 (до `5573h`), а армия на войне теряет силу на `(79Eh · сумма сил врагов в регионе) >> 16`.
- `Snapshot` (10CA0): запись идущей миссии в свой регион (`[1CC8]·[1CC5] + [1CC7]`) из участников (шаг `F5h`) и состояний армий (шаг `1A35h`); клетка военачальника — через 1ECA0.
- `End` (110C8): число регионов без врагов игрока; при семи и свободном третьем регионе состояние кампании `[1EC6]` = 3.

- `OriginalCampaignLosses.Apply` (10FDE, `campaign-losses.json`): потери армии за время вне миссии — слабеющие юниты падают до минимального состояния шаблона (DAT[46]) в пределах бюджета силы.
- `OriginalCampaignCatchup` (10E19 `Away`, 10ECE `Budget`; `campaign-catchup.json`): при входе в регион возвращает отношения участников из записи региона, передаёт потери 10FDE и гонит мир порциями по `400h` обновлений. Середина 10ECE (10EF0..10FC1) — мёртвый код.

Прокрутка шагов мира 11087 (вызывает 42BB, 96CD, D3E5, 1E7EA, 9BF9) и обработчики кнопок меню 111C5..11441 пока не перенесены.
