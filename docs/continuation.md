# Продолжение переноса в новой сессии

Этот файл фиксирует состояние после PR #68 и последовательных срезов интерфейса (группа, клавиши, пауза, курсор, шкалы). База — `main` в `AlexandrVolkov/northwind`; текущая работа ведётся отдельно в **`codex-work`**. Сначала прочитайте [AGENTS.md](../AGENTS.md), [план](port-plan.md), [карту логики](game-logic-map.md) и [реестр покрытия ассемблера](assembly-progress.md). Перед изменениями проверьте `git status` и обновления удалённой ветки.

## Цель и договорённости

- Перенести «Орду: Северный ветер» целиком на **Godot 4.7.2 .NET / C# и .NET 10 LTS**, оставив понятную структуру для модификаций. Различать правила, подтверждённые исходными машинными инструкциями и ресурсами, сведения игрока и временные правила опытной схватки.
- Пользователь работает на Windows 11. Подготовленные изображения, первая карта, сценарий и таблицы уже лежат в `assets/imported`; для **запуска текущей версии** не нужен ISO, Python или повторный импорт. Нужны .NET-сборка Godot и SDK 10. Оригинальный ISO нужен только для нового исследования или подготовки других ресурсов.
- Актуальное указание пользователя: **работать в ветке `codex-work`, без слияния в `main`**. Оно заменяет прежнее разрешение на автоматическое слияние. В Git нельзя добавлять исходный ISO, NORWIND.EXE, DAT/WRK, их побайтовые листинги, локальные SQLite-базы анализа и кэши.

## Что уже есть

Текущий запуск — **экспериментальная схватка на первой карте**, не кампания. В ней есть исходная расстановка выбранных отрядов, групповые приказы, движение с несколькими перенесёнными ядрами, исходные операции боя, стрел и смерти; ИИ противника ещё подключён частично. Работают рабочие, лес и доставка древесины в лесопилку, фермы и прирост людей, строительство казарм и независимые очереди ополченцев. Шахта строится по DAT, определяет тип и начальный запас руды, выдаёт мешки рабочему; рабочий доставляет их в замок и пополняет запасы золота или металла. Текущие границы описаны в [схватке](playable-skirmish.md), [найме](recruitment-production.md) и [добыче](ore-extraction.md). HUD использует графику оригинала; его ввод и отмена ожидающего приказа проверяются режимом `hud`.

`data/skirmish.json` содержит временные параметры и состав миссии (здоровье, урон, темп и частота тактов теперь исходные). Не выдавайте эти величины за исходный баланс. `data/reverse_engineering/annotations.json` — редактируемый реестр исследованных диапазонов; `docs/assembly-coverage.json` и `docs/assembly-progress.md` показывают пробелы. Фикстуры `tests/fixtures` хранят входы и результаты сравнений, а не оригинальный код.

## Последние срезы

- **Панель команд (`codex-work`)** — исправлен разбор шести записей DAT: указатель ведёт к тексту, а не к WRK. Схема `interface.json` обновлена до 2. Видимость одиночной панели фильтруется по OBE[0F], сверена с `6EC1..6F17` на 1280 случаях; пересечение общих команд группы проверено по `B72D..B762` ещё на 1600 случаях. Кнопки рабочего «Стоять», «Идти», «Рубить лес», «Обслуживать шахту» связаны с существующими командами мира; целевой режим не превращается в произвольный контекстный приказ. Исходный обход цепочки выделения и остальные режимы ещё впереди; [подробности](interface.md).
- **Добыча руды** — [ore-extraction.md](ore-extraction.md): шахта → рабочий → замок, 1 — золото, 2 — металл.
- **Клавиши команд (`codex-work`)** — доступные команды вызываются по scan code из DAT: C/B/F, у рабочего H/J. Используется физическая клавиша Godot, в том числе при русской раскладке. Home/End всегда доступны для замка/героя. Подсказки и обводка ожидающей команды — адаптер обратной связи; [ограничения](interface.md).
- **Пауза (`codex-work`)** — игровой ввод и камера замораживаются вместе с симуляцией, Esc продолжает игру. Это адаптер по описанию игрока; исходный DOS-цикл паузы ещё требует отдельного исследования. Проверка — режим `pause`.
- **Обычный курсор (`codex-work`)** — в Git включены 15 кадров WORK.SPR 0..14; числовая анимация `3DB5..3DF1` проверена на 35840 случаях. Программный указатель масштабируется вместе с интерфейсом и останавливается на паузе. Специальные курсоры и их диспетчер ещё впереди. Проверка — режим `cursor`.
- **Шкалы (`codex-work`)** — исправлено направление заполнения и округление здоровья; показываются критический цвет и реальный опыт. 1314 растров оригинального `6DEF` совпали с C#, графический режим проверяет пиксели. Текущая схема `interface.json` — 3 с цветами VGA. Проверка — `status-bars`.
- **Бой (ядро)** — [combat.md](combat.md): формула урона BFC9 с защитой DAT[44], атака 5 + опыт/64, поиск цели 982B, эффект удара, жизненные показатели 90E9 (регенерация, кровотечение, отдых, бегство, опыт). Здоровье в схватке — исходный OBE[19].

## Облачная среда

Окружение `northwind` ставит инструменты setup-скриптом и восстанавливает готовые Godot 4.7.2 .NET (`/opt/godot`, команда `godot`) и Ghidra 12.2 (`/opt/ghidra/current`, подключена к REA) из ветки `toolchain`. Вручную: `git fetch --depth 1 origin toolchain:refs/remotes/origin/toolchain && git worktree add /tmp/tc origin/toolchain && bash /tmp/tc/install.sh`. .NET SDK 10.0.4xx — `/opt/dotnet`, нужен `DOTNET_ROOT=/opt/dotnet`. Игру распаковать из ISO: `7z x` образа, затем `unshield -d install x Setup/data1.cab`; файлы — в `install/Program_Executable_Files`. Pull request создаётся через REST (`gh api repos/.../pulls`), GraphQL и релизы в облачной сессии недоступны.

## Быстрая проверка

Из корня репозитория, с установленными SDK 10 и **Godot 4.7.2 mono**:

```sh
dotnet build
godot --headless --editor --path . --quit-after 120
godot --headless --path . tests/TestRunner.tscn -- simulation
godot --headless --path . tests/TestRunner.tscn -- scene
godot --headless --path . tests/TestRunner.tscn -- hud
godot --headless --path . tests/TestRunner.tscn -- mine
godot --headless --path . tests/TestRunner.tscn -- original-ore
python -m unittest discover -s tests -p 'test_*.py'
```

Здесь `godot` означает .NET-сборку точной версии; при другом имени команды укажите полный путь. Дополнительные режимы `production`, `population`, `economy` проверяют связанные хозяйственные циклы. Графические изменения проверяйте в оконном режиме. Если меняется конвертер или отслеживаемый атлас, проверьте также импорт и сцену из **чистой копии отслеживаемых файлов**. Исследовательские генераторы фикстур требуют оригинальных файлов и Python-зависимостей из `tools/requirements-research.txt`; запуск схватки их не требует.

При обновлении пометок ассемблера синхронизируйте отчёт по [инструкции](assembly-database.md), затем фиксируйте `annotations.json`, `assembly-coverage.json` и `assembly-progress.md` вместе. Указывайте границы проверенного участка и оставшиеся неизвестные ветви: пометка `ported` для одной операции не означает, что перенесён весь обработчик.
