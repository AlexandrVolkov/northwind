# Окно дипломатии оригинала (C11, в работе)

Адреса ниже — смещения LE:1, если не сказано иное. Сопоставлены код
`NORWIND.EXE`, данные LE:3 и запущенная DOS-версия с локальным
`GAME_00.SAV`. Оригинальные SAV/EXE/ISO в Git не добавляются.

## Кнопка и условие открытия

Виджет LE:3 `1B3` соответствует WORK.SPR 227–228 («Дипломатия»,
141×31) и вызывает `EBD8` (см. [work-large-sprites.md](work-large-sprites.md)).
`EBD8..EC37` перебирает отношения текущего участника
`[97A+F5h×local+B9h+i]` для 16 кандидатов. Нулевое отношение
пропускается. Для ненулевого `1EAD8` находит блок участника;
`[EDX+19F1h]` должен быть строго больше `7CFh` (1999). При первом
подходящем участнике `EC2D` передаёт шаблон LE:3 `3B27` в `DEE4`.
Если подходящего нет, обработчик возвращается на `EC37` без окна.
Называть порог 1999 «населением» только по этой проверке рано.

В исследованном SAV у местного участника 0 ненулевые отношения с
участниками 3, 4, 7; показатель двух первых выше 1999, у третьего 0.
На живом экране видны **ровно два** портрета. Это подтверждает оба
условия отбора. Снимок: [original-diplomacy-contacts.png](reference/original-diplomacy-contacts.png).

## Группы окон

`DEE4..DF26` читает заголовок группы: u32 длина блока виджетов,
u32 callback инициализации, u8 номер группы, затем копирует виджеты
в рабочую таблицу и вызывает callback. У этих четырёх групп длина
`1Eh` (один 30-байтный виджет):

| Шаблон LE:3 | Группа | Инициализация | Надпись после виджета | Этап |
|---|---:|---:|---|---|
| `3B27` | 1 | `E65B` | «Выберите народ» | доступные контакты |
| `3B5D` | 2 | `E717` | «Их предложения:» | входящие сообщения выбранного народа |
| `3B94` | 3 | `E81A` | «Наши предложения» | исходящие варианты |
| `3BCC` | 5 | `E9F0` | «Послать ответ» | ответ на сообщение |

Первые три этапа подтверждены естественными снимками:
[контакты](reference/original-diplomacy-contacts.png),
[их предложения](reference/original-diplomacy-incoming.png),
[наши предложения](reference/original-diplomacy-outgoing.png).
Этап ответа на входящее предложение в этом сохранении не показан.

## Размещение контактов

`E65B..E716` составляет список номеров участников в `[1F45]` и
завершает его `FFh`. Своего участника исключает. Если контактов
не больше четырёх, он создаёт один ряд; если больше — два ряда по
`ceil(n/2)` и `floor(n/2)` портретов. Для каждого ряда начальная
X-координата — `240 − 56×число_в_ряду`; последующие X растут на
112. Первый ряд имеет Y=130, второй Y=280 (`+150`). Портреты
создаются через `EAD8`. В образце с двумя контактами получаются
аргументы `(128,130)` и `(240,130)`, что соответствует двум видимым
портретам.

`EAD8..EBD7` добавляет три 30-байтных виджета на участника:
портрет `WORK.SPR 0C3h + participant[B8h]` в `(x,y+35)`, значок
отношения, выбранный по `participant[B9h+local]`, и строку имени
из `participant[A4h]`, центрированную под портретом. Точные границы
нажатия и смещения внутренних изображений продолжают проверяться.

## Переходы по кликам

Живой оригинал: нажатие «Дипломатия» открывает выбор контактов; нажатие
первого портрета показывает его окно «Их предложения:»; повторное
нажатие портрета переводит к «Наши предложения». В образце видны два
варианта исходящего сообщения. Нажатие второго варианта закрывает
окно; само попадание сообщения в очередь этим снимком не доказано.
В коде callback портрета `EC38..EC60` сохраняет выбранный номер в
`[DD4]`, удаляет текущую группу через `E5E6` и открывает `3B5D`.
Участок `EC82..ECA2` переключает на `3B94`.

Локальный граф `build/diplomacy-ui-call-graph.md` строился от
`E861/F629`; вне диапазона находятся `7012`, `704F`, `A4A9`, `DF7E`.
Полный модальный цикл, ответ, сроки очереди и C#-встраивание в HUD
не входят в этот срез. Ядро отношений и сообщений уже описано в
[diplomacy.md](diplomacy.md).
