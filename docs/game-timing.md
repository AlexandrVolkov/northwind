# Частота обновлений и порядок такта

Частота мира установлена по коду NORWIND.EXE (адреса LE:1).

## Таймер

**418A..419B** программирует канал 0 PIT (`out 43h, 3Ch`) делителем **4000h**: 1 193 182 / 16 384 = **72,82 Гц**. Обработчик **41C6** увеличивает счётчик `[19E4]` и каждый четвёртый тик вызывает прежний обработчик BIOS (чтобы системное время шло с обычной частотой 18,2 Гц). При выходе **41EB** возвращает делитель FFFFh.

## Скорость игры

**A10B..A176** в начале каждого прохода основного цикла (319F) разрешает шаг мира (`[1C4E] = 1`), если с прошлого шага прошло не меньше `FFh − [908E]` тиков таймера. `[908E]` — настройка скорости: начальное значение **FDh** (11293/112BB), клавишами меняется в пределах F0h…FEh (A12B..A151).

| [908E] | Тиков на шаг | Шагов мира/с | Обновлений объектов/с |
| --- | ---: | ---: | ---: |
| FEh (быстрее всего) | 1 | 72,8 | 36,4 |
| **FDh (по умолчанию)** | 2 | 36,4 | **18,2** |
| F0h (медленнее всего) | 15 | 4,9 | 2,4 |

## Порядок шага

Основной цикл 319F..321C вызывает, в частности, **42BB** (объекты) и сразу затем **96CD** (эффекты: стрелы, искры, трупы).

- **42BB**: при разрешённом шаге уменьшает `[1C4F]`; обновление объектов идёт только когда он достигает 0, затем снова 2 — то есть **через шаг**. В этот момент увеличивается глобальный байт такта `[19EA]` (по нему работают «раз в 16/256 тактов» в шахте, замке, отдыхе и росте опыта) и для каждого участника по цепочке объектов вызывается обработчик AH=1 (430E..4343, там же `[1C49]` = DAT объекта).
- **96CD**: при каждом разрешённом шаге обновляет все эффекты массива `[6B2]`.

Значит, при скорости по умолчанию эффекты обновляются **вдвое чаще** объектов: стрела пролетает 15 px за шаг эффекта, т.е. ~546 px/с.

## В схватке

`Rules.TicksPerSecond` = 18,2065 обновлений объектов в секунду (`data/skirmish.json`), эффекты стрел — два шага на одно обновление объектов. Прежние экспериментальные 30/с убраны. Мостовая задержка перепланирования маршрута выражена в тактах (21), а не секундах. Смена скорости игры клавишами пока не подключена.

Порядок в схватке: стрелы → смерть → здания (отдельными проходами) → юниты по владельцу в порядке списка с исходным хвостом 434D..4384 (см. combat.md). Полное слияние зданий и юнитов в одну цепочку участника — мост.
