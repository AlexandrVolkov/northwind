# Дерево развития (TRE)

Статус: **формат разобран, базовые операции перенесены и сверены** (A673, A6AE/A6F9, A716, 223B4). Исполнитель исследования лаборатории перенесён (ниже); интерфейс покупки игроком — ещё нет. Адреса — LE:1.

## Формат ARMY__0x.TRE

Последовательность записей переменной длины, затем тексты (CP866, конец строки FFh):

| Смещение | Поле |
| --- | --- |
| +0 | вид: 0 — исследование, 1 — «после постройки шаблона», 2, 3 — особые; **бит 7** — открыто/выполнено (у шаблонов 80h — шаблон известен) |
| +1 | номер (для вида 0/80h — индекс шаблона DAT или исследования) |
| +2 | число невыполненных условий |
| +3 | u32 — смещение текста от +3 (0 — нет) |
| +7 | u32 — стоимость (300/500/1000) |
| +0B..+0E | не разобрано (нули), сохраняется |
| +0F | число потомков |
| +10 | u16 потомки: (вид, номер) |

Список кончается записью с `+1 = FFh` (в файлах — `FF FF`). Каждое поселение работает со своей копией: указатель `[6CA + 56h·армия + 15h + 4·владелец]` (`6DF + …` в 23C11/A673/A716).

## Операции

- **A673** — шаблон открыт: есть запись `(80h, номер)` и её `+2 = 0`; обход до записи с `+1 = FFh`.
- **A6F9** — поиск записи по слову (вид, номер); обход до записи с `+0 = FFh`.
- **A6AE** (AL = номер, AH = вид; владелец — `[ESI+3]`, армия — `[ESI]`) — пункт выполнен: `+0 |= 80h`, у каждого потомка `+2` уменьшается командой DEC, а отрицательный результат (бит 7) становится нулём. Вызывается при завершении постройки (вид 1) и исследования (вид 0, CD44).
- **A716** (AL = владелец, AH = армия) — список доступных исследований: записи с `+0 = 0` и `+2 = 0`; первая запись проверяется до условия конца; заголовки по 16 байт копируются в 1F45.
- **223B4** (AL — учитывать A673, AH — армия, BL — владелец, ECX/EDX — маска и значение DAT[40]) — номера шаблонов армии с `DAT[40] & маска = значение` и `DAT[9C] ≠ FFh`, список в 1F45, конец FFh.

## Перенос и сверка

`scripts/OriginalTechRules.cs`; данные — `data/original_tech.json` (`tools/tech_source.py`: записи и тексты, без сырых байтов файла; C# восстанавливает область записей и сверяет её SHA-256 с файлом). Сверка: `tools/verify_tech.py` — 1500 последовательностей операций на изменённых копиях деревьев армий 0–2 под Unicorn; режим `original-tech`; мутации ловятся.

## Исследование в лаборатории (LE:1 CCCB, FS 81) — перенесено

`OriginalLabResearch` (`scripts/OriginalLabResearch.cs`), сверка — `tools/verify_lab.py`, `tests/fixtures/lab.json` (4000 случаев; A716, 9E41 и A6AE — записанные заглушки). Каждое обновление лаборатории: без текущего исследования (`+15 = 0`) берётся случайный пункт списка A716 (`(9E41 · число) >> 8`), в `+28` его номер, в `+24` цена, `+15` растёт. Раз в 256 обновлений (младший байт счётчика `[19EA]` = 0) со третьего запаса участника (`+20`) списывается `10 · +23 · +22` (байтовая арифметика; `+22 = +23 = 1` у новой лаборатории, ИИ ставит 5 в 23C11), неоплаченный остаток уменьшает цену разностью с переносом, как в оригинале; при нуле пункт выполняется (A6AE, вид 0), `+15` падает, счётчик поселения `+73` теряет 271h. Там же перенесены события развития: десятый выпущенный боец класса 8 (ополченец, рыцарь) открывает событие (2, 8) — исследование рыцаря, десятый класса 9 (лучник, поджигатель) — (2, 9), строительство при поддержке ферм 28h..32h — (2, 0) — конюшня (A9A4..AA36, AFDB).

В схватке лаборатория ИИ исследует катапульту, конюшню и балисту (событие 3/200 «находка медвежьих жил» принадлежит кампании ARMY__05 и здесь не наступает — балиста недоступна), затем ИИ строит конюшню, мельницу, церковь, обучает всадников и рыцарей. **Открытая проблема:** катапульты и баллисты, выбранные для пополнения армии и охраны (20DD0 режимы 8 и 1), в схватке не дают армии выйти в поход (отряд не отчитывается «готов»; сами машины ходят), поэтому адаптер `ArmyFill` исключает их из этих двух выборов; причина не найдена.
