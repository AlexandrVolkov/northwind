# Автомат подхода к лесопилке

Перенесён блок **EXE 8F70..902E** с настоящей проверкой цели через WRK лесопилки и связанный автомат поворота **9354..937D**. Схватка использует его фазы и счётчики повторов; сам маршрут по-прежнему строит Godot AStarGrid2D. Полный игровой диспетчер и исходный планировщик этим этапом не объявляются перенесёнными.

## Цель и результат

**8A7F → D182** разрешает относительную ссылку OBE.u32[1C], передаёт посетителя в EDX и вызывает у получателя **AH=5**. Для лесопилки **ARMY__02.WRK 363..382** проверяет DAT посетителя: результат положителен, если установлен бит **1000** либо `(flags & F00) == 300`. Ветка бита 1000 выполняет `XOR AL,AL`, то есть возвращает ZF=1; нельзя трактовать её как отказ. Новое ядро ограничено этим WRK-валидатором, а не произвольными обработчиками зданий. При нулевой ссылке или отказе очищается бит 40 рабочего и возвращается отказ BL=2.

Результат 8F70 определяется **ZF и BL**, не только AL. `ZF=0` означает ожидание/продолжение; при `ZF=1` BL=0 — завершение взаимодействия, BL=1 — исчерпанные попытки движения, BL=2 — недопустимая цель/точка или истёкшее ожидание ответа. C# возвращает эти результаты явно, а запросы движения и остановки — отдельными признаками.

## Фазы OBE[30]

Младший полубайт задаёт фазу, старший — счётчик:

- **0, 8F94..8FBC.** При активном движении (младший OBE[2D]=2) сначала запрашивается покой через 8C98. Иначе записывается **91**, вычисляется исходная точка входа через 8DB0 и ставится запрос движения **8CA1**: клетка в OBE[22]/[23], старший полубайт OBE[2D]=2.
- **1, 8FBD..8FF5.** Пока анимация/движение активны либо текущий и запрошенный типы различаются, счётчик не меняется. В покое снова вычисляется точка. Для ненулевого смещения входа нужны **точные координаты**; для центра используется 9B86 и зазор областей меньше 32. При прибытии OBE[30]=02. Иначе из байта вычитается 10h и повторяется запрос; при заёме возвращается BL=1. Всего возможны первоначальный запрос и **девять повторных**. Истощённый байт остаётся F1 до обработки результата вызывающей стороной.
- **2, 8FF6..900B.** Через 8BEA запрашивается окончание текущей анимации либо выполняется исходный поворот к центру здания. Только при готовности выставляются оба бита 40 и OBE[30]=F3 — [ранее перенесённый запрос передачи](worker-delivery.md).
- **3, 900D..902E.** Ожидание ответа и байтовый таймер используют прежнее проверенное ядро. Снятие бита 40 завершает взаимодействие; нулевой счётчик даёт отказ. Фазы 4..15 исходный блок оставляет без изменений, сохраняя результат продолжения; перенос не добавляет произвольный сброс.

**9B86..9BF8** вычитает из модулей разности координат половины размеров обеих областей. Сдвиги ширины/высоты выполняются в байтах, затем отрицательный по старшему биту результат прижимается к 0; возвращается максимум по двум осям. u32-переполнения и знаковые проверки сохранены. Для реальной лесопилки остаётся ветвь точного входа −80,+16; ветвь центра проверена отдельными профилями.

## Поворот

**9210** направляет стационарное состояние 1 в **9360**; переход к нему проходит через **9275 → 9354**. На входе OBE[26]=2, затем в том же вызове он уменьшается до 1. При дальнейшем уменьшении до 0 загружается 1 и вызывается **9653** с желаемым направлением из старших битов OBE[25]. Когда native ZF подтверждает окончание, OBE[2D] обнуляется. Запрос другого состояния во время поворота не переносится автоматически за его завершение. Существующая особенность ZF при нулевом номере кадра также сохранена.

`OriginalWorkerAnimation` теперь поддерживает стационарные состояния **0/1/3** и такие же запросы. Состояние движения 2 исполняет отдельный мост. Все кадры поворота уже есть в готовом атласе; новые ресурсы и импорт из ISO не нужны.

## Связь со схваткой

`OriginalWorkerApproach.Step` проверяет цель и исполняет одну фазу. При запросе движения мост строит путь Godot и исполняет его через ранее перенесённые ядра. Весь активный маршрут обозначается состоянием 22; оно сохраняется между клетками, чтобы попытка не списывалась на каждую клетку длинного пути. При отсутствии пути запрошенное движение заканчивается в покое, и следующее обновление ядра уменьшает счётчик. Начало движения откладывается до следующего обновления после постановки запроса.

При результате BL=1/2 мост очищает текущую доставку и возвращается к выбору получателя. Занятый вход не уничтожает груз; после освобождения движение возобновляется. Потеря цели сбрасывает маршрут, заканчивает уже начатый шаг занятости, затем выбирается другой подходящий получатель. Поворот перед запросом передачи теперь проходит через исходный таймер состояния 1, а не повторяется без анимационной паузы каждый кадр.

Границы: путь, обработка его неудачи, завершение текущего клеточного шага при отмене, повторный выбор после результата ядра и порядок глобальных обновлений остаются мостом Godot. Выбор/сохранение цели дополнительно проверяет своё живое здание и условие пригодности C439; сама WRK-проверка AH=5 состояния здания не проверяет. Прежнее ограничение запроса передачи до полного окончания стройки сохранено. Общий префикс 90E9, полный диспетчер 8227 и все состояния рабочего ещё не подключены. Частота тактов и цены остаются экспериментальными.

## Проверки

`tools/verify_worker_approach.py` выполняет **весь 8F70**, включая 8A7F, настоящий WRK AH=5, выбор DAT, 8DB0, 9B86, 8BEA, 960B/9653 и запросы 8CA1/8C98. Поток управления ограничен; возврат проверяется. Признаки запросов снимаются на исходных границах вызовов, а результат — по ZF/BL. Исследовательский `--trace` по желанию сохраняет локальные записи для поиска первого расхождения; они не нужны обычным тестам и не включены в Git.

- **157 696** шагов подхода: все 256 значений OBE[30], 11 сочетаний текущего/запрошенного состояния, четыре профиля флагов посетителя, два направления и семь пространственных/кадровых профилей. Сравниваются полные 54 байта рабочего, 37 байт получателя, статус и запросы. Профили включают точное прибытие, заблокированное/далёкое назначение, точку вне карты, зазор центра 31/32 и u32/байтовые переполнения.
- **1** отсутствующая ссылка с очисткой флага без чтения получателя.
- **266 240** шагов поворота: все байты таймера, направления 0..63/FF, текущие и запрошенные состояния, флаг остановки, обычная и предельная база/шаг кадров. Сравнивается вся запись; эффект удара не должен возникать.
- **Всего 423 937** случаев совпали с x86. Прежние эталоны рубки, доставки и движения сохранены.

Сквозной `economy` ставит союзника во вход, проверяет расход/исчерпание счётчика и паузу, освобождает вход и доводит семь доставок до вырубки. Затем удаляет выбранную лесопилку во время подхода и проверяет сохранение груза, выбор второй и единственное зачисление. Проверки работают на включённых в Git данных:

```sh
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-worker-approach
godot --headless --path . tests/TestRunner.tscn -- economy
```

Исследовательское воспроизведение требует оригинальной установленной игры и Unicorn:

```sh
python tools/verify_worker_approach.py --game /путь/к/игре --fixture /tmp/worker-approach.json
```
