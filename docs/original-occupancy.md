# Начальная занятость и запись областей по EXE/WRK

[OriginalOccupancyMap.cs](../scripts/OriginalOccupancyMap.cs) переносит запись и очистку прямоугольников занятости. Импортёр 10 создаёт `scenario.json` версии 2 с проверенным профилем начальной регистрации. `Main` загружает эту сетку отдельно от демонстрационной симуляции. Нужен повторный импорт.

## Память и ссылки

Выделение в EXE **420D..426E** резервирует `13 × width × height + 128` байт. Указатели **18CE/18D2/18D6** адресуют три плоскости u32, **18DA** — байтовую видимость. Инициализация **24D9..2509** заполняет три плоскости нулями, видимость — FF. Четвёртой плоскости занятости здесь нет. Видимость пока не перенесена.

Загрузчик **2EA0**, запись файла в **2FD7..2FDB**, помещает OBE на единицу дальше начала каждого 64-КиБ блока. Относительная ссылка:

```text
runtime_reference = slot_index × 65536 + 1 + file_offset
```

Поэтому у первого замка первой карты ссылка **1**, хотя его смещение в файле равно нулю. Ноль в клетке означает отсутствие объекта. Snapshot сохраняет словарь ссылок всех записей, включая не зарегистрированные на выбранной фазе.

## Запись прямоугольника

**43E5 → 6885 → 43B0 → 4409** получает размеры из DAT[3:5], вычисляет начало как `(raw_coordinate >> 5) - floor(size / 2)` и выбирает плоскость через **OBE[0x0D] & 3**. Внутри допустимой области все клетки безусловно заменяются входным u32. Ноль очищает область; проверки владельца прежней клетки в этом обработчике нет. Обёртка 43E5 восстанавливает все четыре байта глобального размера по 273F.

Нативный писатель не проверяет границы. C# поддерживает только ненулевой размер и область целиком внутри карты, плоскости 0..2; другие входы отклоняются до записи. Совместимость вне этой области не заявляется. Это ограничение отличается от байтового переполнения в ранее перенесённой функции проверки места.

**D2D1..D362 при CL=0** заменяет клетки, равные `expected`. Остальные ненулевые клетки, не равные `replacement`, увеличивают счётчик конфликтов — по клеткам, а не по уникальным объектам. Вариант с повреждением чужих объектов не перенесён. Начальная регистрация «Кувш. фантома» использует `expected=0`, `replacement=self`, `CL=0`, то есть занимает только пустые клетки.

## Профиль начальной регистрации

Исследовательский инструмент исполняет настоящие префиксы WRK с AH=1 и счётчиком FS=1, до входа в **81D9** или **D2D1**, либо до возврата. Выполняются реальные вызовы поиска шаблона; допустимые выходы из WRK ограничены адресами. Проверяется неизменность пространственных полей. В 81D9 общий писатель исключён при `DAT.flags & 0x40000`; такие шаблоны классифицируются отдельно без исполнения всего специального скрипта.

Для всех 2 002 записей из 12 SCN получены:

| Политика | Записей |
| --- | ---: |
| Обычная перезапись | 1 851 |
| Условная регистрация в пустых клетках | 8 |
| Исключение общего писателя флагом 40000 | 141 |
| Возврат без регистрации на выбранной фазе | 2 |

Последние две записи относятся к драконам; это не означает постоянного отсутствия занятости или объекта. Сетка строится в порядке слотов SCN и записей OBE с сохранением приоритета перезаписи. Ожидаемые хэши получены исполнением нативных писателей. Для первой карты: 80 объектов, 68 обычных регистраций, одна условная, 11 исключений, ноль конфликтов.

Это **начальная геометрия общей регистрации**, а не полный первый такт игры: здесь нет движения ранее обновлённых объектов, видимости, эффектов, порождения объектов и ИИ. Полный пространственный жизненный цикл и окончательные разрешения строительства ещё восстанавливаются.

[occupancy-profile.json](occupancy-profile.json) содержит хэши EXE, SCN, MAP, связанных OBE/DAT/WRK и результаты. Обычный импорт использует профиль без Unicorn. Если исходные файлы изменены или сценарий неизвестен, ставится `initial_occupancy.status=unavailable`, а ссылки и политики остаются непроверенными. Пустая сетка вместо неизвестной не подставляется. Для модифицированных данных нужен новый профиль или будущий полноценный инициализатор; текущая проверка хэшей не ограничивает API изменения уже созданной сетки.

## Воспроизведение и проверки

```sh
python -m pip install -r tools/requirements-research.txt
python tools/verify_occupancy.py --game /путь/к/игре --fixture /tmp/occupancy.json --profile /tmp/occupancy-profile.json
python tools/import_game.py /путь/к/игре
dotnet build
godot --headless --path . tests/TestRunner.tscn -- simulation
godot --headless --path . tests/TestRunner.tscn -- imported-occupancy
godot --headless --path . tests/TestRunner.tscn -- scene
```

`godot` должен быть .NET-версией 4.7.2. [Синтетический эталон](../tests/fixtures/occupancy.json) содержит параметры и хэши **7 968** безусловных и **31 872** условных записей: пять размеров, все допустимые положения в карте 8×8, шесть значений слоя, нулевые/ненулевые клетки и границы u32. C# сравнивает все результаты с x86. Оригинальные байты в Git не добавляются.

`imported-occupancy` проверяет весь буфер и словарь ссылок без зависимости от вида карты. Проверка пройдена для всех 12 сценариев, включая дополнительные файлы 21/22; это перечень файлов образа, а не доказанная топология кампании. Сценовый тест первой карты проверяет блокирование исходным замком, очистку его области и повторное занятие записью нового замка. Это связка с `ProbePlacement`, а не готовое пользовательское меню строительства.

Продолжение: [фаза движения и отсоединение записей](spatial-movement-removal.md) добавляет перенос занятости при пересечении середины шага и очистку при удалении по исходным флагам. Полный первый такт по-прежнему не перенесён.
