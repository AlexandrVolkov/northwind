# Исходный поиск обхода

`OriginalRouteSearch` переносит автомат поиска `73F5 / 7497–79BF` из восстановленного LE-кода `NORWIND.EXE` в C#. **294 карты, 272 362 вызова проверки соседей** совпали с прямым исполнением оригинала: сравниваются направления пути, конечные координаты поиска и полная упорядоченная последовательность проверок. Это не только сравнение длины пути или изображения.

В схватке исходный автомат теперь строит локальные маршруты для отрядов и рабочих, включая диагонали. Для дальних приказов пока сохранён временный подбор промежуточных целей через AStar; исходная координация движения и ИИ ещё не восстановлены полностью.

## Что восстановлено

Источник: `NORWIND.EXE`, SHA-256 `eb52f043143d763f5a595ae2175249976f278d1eebf0336ae032caf7bfa0c3a8`. Адреса ниже относятся к LE-коду.

| Участок | Правило |
| --- | --- |
| `73F5–7497` | Подготовка размера объекта, слоя, маски владельца, начального левого верхнего угла области и границ обхода ±16 клеток |
| `7497–7529` | Начальные проверки: совпавшая цель и наличие хотя бы одного допустимого соседа; соседи проверяются в порядке 7 → 0 |
| `7529–7647` | Восстановление выбранной ветви, вращение направления вокруг препятствия, запись поворотных точек |
| `7647–76B8` | Прямой ход к цели и создание развилки; направление определяется знаками разностей, без сглаживания угла из `9688` |
| `76B8–77D8` | Обнаружение повторного посещения, выбор ближайшей ветви, оценка длины и переключение маски ветвления |
| `77D8–79BF` | Выбор полного или частичного результата, обход записанных точек и выдача байтов направлений с терминатором |
| `79C0–7A03` | Восемь направлений по знакам разностей координат; `FF` для совпадения |
| `7F34–7FA7` | Сдвиг текущего угла области, проверка повторного посещения и локальных границ |

Рабочий буфер начинается по `1F45`; граница записи точек — `2723`, выдачи направлений — `272B`. Маркеры `80/81` отличают конец ветви и развилку от координат. Стек содержит до восьми семибайтных записей. Реализация сохраняет переходы исходного автомата и порядок выбора при равной оценке; метки в C# соответствуют участкам таблицы. Она не исполняет машинные инструкции и не загружает EXE во время игры.

Направления: 0 север, 1 северо-восток, 2 восток, 3 юго-восток, 4 юг, 5 юго-запад, 6 запад, 7 северо-запад. Один диагональный шаг изменяет обе координаты на клетку; его движение выполняют уже перенесённые ядра.

### Особенности, которые нельзя заменять обычным AStar

- Начало и цель адресуют **левый верхний угол** области объекта. Адаптер переводит клетку якоря пользовательского приказа в эту систему координат.
- Вращение направлений, маска ветвей, восьмибитная длина и выбор при равной оценке имеют конкретный порядок.
- Проверка шага рассматривает область **назначения**. Дополнительной проверки двух ортогональных клеток при диагонали здесь нет.
- Границы ±16 вычисляются с байтовым переполнением. Это ограничения обхода, а не обрезка всей карты перед поиском.
- `7F7D` при совпадении с локальной границей возвращает одновременно CF и ZF. Прямой ход и обход используют эти флаги по-разному. Подмена их одним признаком «достигнута конечная цель» меняет частичные маршруты.
- Если полного пути нет, автомат может выдать путь к промежуточной точке. Такой результат нельзя считать достижением исходного приказа.
- Реализация ограничена картами до 128×128, как проверенные игровые карты: старший бит координаты X используется для маркеров. Большие карты нельзя просто включить без изменения формата.

В C# есть защитный лимит операций для ошибочного/изменяемого callback. При превышении возникает явная ошибка; он не выдаётся за исходный такт или бюджет поиска и не возвращает выдуманный путь.

## Подключение и временные правила

`Skirmish.SearchPath` сначала обращается к исходному автомату. Выданный путь попадает в [оригинальный пул](native-route-storage.md), а каждый следующий шаг повторно проверяется перед движением. Препятствие, появившееся после поиска, отменяет текущий маршрут, сохраняя конечный приказ.

Проходимость использует [перенесённое ядро допуска](movement-admission.md), но прототип продолжает считать все мягкие контакты занятыми клетками и учитывать собственные временные резервы. Исходный `7D4C` допускает статусы 1/2/3 как кандидаты; последующее ожидание/взаимодействие `7FA7–811F` перенесено лишь частично. Поэтому полная система столкновений оригинала не объявляется воспроизведённой.

На первой карте при дальнем нападении локальный поиск с этой консервативной проходимостью может остановиться у реки. Чтобы сохранить существующий игровой сценарий:

1. При отсутствии продвижения для данного приказа адаптер включает подбор промежуточных целей через Godot AStarGrid2D.
2. AStar использует восемь соседей и оценку Чебышёва; его клетки не становятся непосредственно исполняемым маршрутом.
3. Из первых 16 клеток подсказки выбирается самая дальняя, до которой исходный автомат действительно выдаёт полный локальный путь. Если нужно, цель сокращается вплоть до соседней клетки.
4. До смены/достижения цели поиск продолжает использовать такие подсказки, чтобы отряд не возвращался к тому же тупику. Статистика `GuidedRouteSearches` делает применение этого режима проверяемым.

Это **временная координация дальнего приказа**, а не восстановленная стратегия оригинала. Бой и выбор позиций атаки тоже остаются экспериментальными. Прямые диагональные приказы и обычные частичные маршруты не требуют подсказок; это отдельно проверено. Оригинальный общий бюджет пяти поисков, связка ожидания/разрушения контакта и вспомогательная проверка достижимости `72FE` ещё требуют переноса.

## Доказательства и воспроизведение

`tools/verify_route_search.py` исполняет настоящий `73F5` вместе с `7497`, `7D4C` и `7F34` в Unicorn. Он готовит карту и DAT, регистрирует порядок входов в проверку соседей и читает выданный результат. Поиск не заменён Python-моделью. Неожиданный переход или исчерпание лимита инструкций считаются ошибкой.

Набор включает:

- Все 64 цели относительно одной стартовой клетки на свободной карте 8×8.
- Стены с проходами разного положения, полностью перекрытые стены, U-образные и замкнутые препятствия; области 1×1, 2×2, 1×2 и 3×2.
- Дальние цели на 128×128, границы ±16, края карты и совпавшие координаты.
- 192 воспроизводимые случайные карты 16×16 с плотностью препятствий 10/25/40/65 процентов.

Всего **294 случая**, **272 362 проверки соседей**, **89 результатов без маршрута** и **86 частичных маршрутов**. Параметры карт и SHA-256 результатов хранятся в `tests/fixtures/route-search.json`; байтов EXE там нет. C# проверяет каждый случай отдельно и общий хэш. Повторное использование одного экземпляра поиска также покрывается последовательным прогоном всех карт.

Связанные проверки проходят через обычные приказы: три диагональных шага, перенос занятости, обход стены, блокирование уже найденного первого шага и новое достижение цели. Сохраняются прохождение двух рабочих через мост, дальний приказ с несколькими исходными поисками, полный древесный цикл и победа в схватке. Последняя отдельно проверяет использование временных подсказок у реки.

```sh
PYTHONPATH=/path/to/unicorn python tools/verify_route_search.py \
  --game /path/to/game --fixture tests/fixtures/route-search.json
dotnet build
godot --headless --path . tests/TestRunner.tscn -- original-route-search
```

Штатные C#-проверки и игра работают без Unicorn, Python, ISO и EXE; ресурсы уже включены в Git. Требуются Godot 4.7.2 .NET и SDK 10.
